---

## 为什么做这个

在带教实习生和自己做项目的过程中，我发现一个反复出现的问题：**方法论都知道，但每次用的时候都要重新想"第一步做什么、产出什么、什么算好"。**

比如"做用户访谈"，大家都知道要访谈，但：
- 提纲怎么设计才不会引导用户？
- 访谈记录怎么分析才能产出洞察而不是流水账？
- 什么样的访谈结论才算"有效"？

这些问题如果每次都靠经验判断，效率低且质量不稳定。于是我把这些方法论**固化成可执行的 Skill**——每个 Skill 就是一个标准化工作流：明确触发场景、输入要求、执行步骤、产出模板和质量红线。

这和做 AI 产品是同一个思路：**把隐性经验显性化，把显性经验标准化，把标准流程自动化。**

## 产品决策

| 决策点 | 选择 | 为什么不选另一个 |
|--------|------|------------------|
| 形态 | `.skill` 文件包（SKILL.md + references/） | 不是写一篇篇文章，而是可执行、可安装、可触发的工作流；文章只能读，Skill 可以直接用 |
| 粒度 | 单一职责，每个 Skill 只干一件事 | 大而全的"AI PM 万能助手"什么都能干但什么都干不好；单一职责便于组合和迭代 |
| 分类 | 用户研究/产品设计/数据分析/求职发展四大类 | 覆盖 AI PM 工作全链路，不是零散技巧的堆砌 |
| 质量保障 | 每个 Skill 必须有质量红线和异常兜底 | 这和做 AI 产品的思路一致：不能只写"正常流程"，必须定义"什么不能做"和"出了问题怎么办" |
| 打包格式 | 标准 .skill（ZIP） | 可直接安装到 Aily 等支持 Skill 的平台，不绑定特定厂商 |
| 内容来源 | 实战经验 + 行业最佳实践系统化 | 不是从书上抄的理论，每个方法都在实际项目中用过 |

## 这是什么

AI PM SkillKit 是一套为 AI 产品经理打造的方法论工具包。每个 Skill 都是一个独立的、可直接调用的工作流——告诉你**遇到什么问题用什么方法、每一步做什么、产出什么**，并附带可直接套用的模板和提示词。

- **系统化**：不是零散的技巧，是完整的 5-6 步工作流
- **可落地**：每个方法都有模板和示例，拿来就能用
- **AI 原生**：针对 AI 产品的特点设计（如 AI 需求四问法、AI 质量指标、五层竞品框架等）
- **单一职责**：每个 Skill 只干一件事，不做大杂烩
- **质量红线**：每个 Skill 都有明确的质量标准和异常兜底
- **即开即用**：打包为 `.skill` 文件，可直接安装到 Aily 等支持 Skill 的平台

## 安装与使用

### 方式一：直接安装 .skill 文件（推荐）

1. 从 [`dist/`](dist/) 目录下载需要的 `.skill` 文件
2. 在支持 Skill 的平台（如 Aily）中导入安装
3. 直接用自然语言触发，例如：
   - "帮我做一份竞品调研"
   - "帮我优化简历，JD 是…"
   - "DAU 跌了，帮我分析一下原因"
   - "根据这份业务调研，帮我设计一套外呼对话策略"

### 方式二：源码使用

每个 Skill 的源码都在 [`skills/`](skills/) 目录下，你可以：

- 直接阅读 `SKILL.md` 学习方法论
- 复制 `references/` 中的模板到自己的工作流中
- 根据需要自定义修改后重新打包

### 重新打包 Skill

```bash
cd skills/
zip -r ../dist/skill-name.skill skill-name/
```

## 每个 Skill 的结构

每个 Skill 遵循统一的目录结构：

```
skill-name/
├── SKILL.md              # 主文档：触发条件 + 输入要求 + 工作流 + 质量红线 + 异常兜底
└── references/
    ├── template-xxx.md   # 输出物模板
    ├── prompts.md        # 提示词合集
    └── examples.md       # 实战案例
```

### 设计规范

每个 SKILL.md 必须包含：
- **触发场景**：明确的触发词和适用场景
- **输入要求**：必需信息 + 可选信息 + 信息不全时的追问话术
- **工作流**：5-6 步可执行步骤，每步有明确产出
- **质量红线**：3-6 条不可违反的质量标准
- **异常兜底**：常见异常情况及处理方式
- **References 索引**：参考文件及读取时机

这个设计规范和 AI 产品设计的思路一致：**定义输入输出、设计工作流、设置质量红线、处理异常情况**。

迭代原则：
- 不堆砌理论，每个方法都要有可落地的模板或步骤
- 每个 Skill 保持单一职责，只干一件事
- 外部数据必须标注来源，不编造数字
- 优先补充实战案例和真实场景
