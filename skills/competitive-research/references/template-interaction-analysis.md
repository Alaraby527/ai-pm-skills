# 交互设计分析模板
> 用于 L5 用户体验层的深度拆解。功能分析关注"有什么"，交互分析关注"怎么用"。同一个功能，不同交互设计可能带来截然不同的体验。

## 一、关键页面选择标准

不需要对每个页面都做交互拆解，选择 3-5 个关键页面：

| 选择标准 | 说明 | 示例 |
|---------|------|------|
| 高频页面 | 用户每次访问都会接触 | 首页、搜索结果页 |
| 核心转化页面 | 承载核心业务转化 | 商品详情页、内容发布页 |
| 已知痛点页面 | 用户反馈多或数据异常 | 加载慢、跳出率高的页面 |
| 竞品差异显著页面 | 布局/交互与竞品差异大 | 在信息采集中发现的差异页 |

## 二、六维度交互拆解表
> 每个关键页面一张。六维度逐一填写"我们怎么做"和"竞品怎么做"，差异点自然浮现。

| 分析维度 | 关注点 | 我们的实现 | 竞品参照 | 差异等级 |
|---------|--------|-----------|---------|---------|
| 信息架构 | 页面元素的组织方式、主次层级、视觉优先级 | | | 核心/体验/无差异 |
| 操作路径 | 完成核心任务需要几步操作、是否有快捷方式 | | | |
| 反馈机制 | 操作后的即时反馈（loading、成功/失败提示、动画） | | | |
| 引导与提示 | 首次使用引导、空状态提示、操作帮助文案 | | | |
| 异常处理 | 错误状态处理、网络异常、数据为空时的表现 | | | |
| 响应式适配 | 不同屏幕尺寸下的布局调整、移动端体验 | | | |

**分析要点：**

## 四、交互质量评分表
> 将六维度拆解结果量化为 1-5 分，所有竞品同一维度横向对比。

| 评分 | 标准 |
|------|------|
| 5 分 | 该维度体验优秀，可作为学习标杆 |
| 4 分 | 体验良好，小细节可优化 |

## 六、交互分析红线
- **最忌讳"看着不顺眼就记下来"**：每条问题必须有竞品参照。如果所有竞品都没有你说的那个交互，那可能不是问题而是行业惯例
- 反过来，如果所有竞品都做了而你没做，那大概率是真问题
- 异常状态（空数据、错误、网络中断）必须覆盖，不能只看正常流程
- 移动端体验单独评估，不能用桌面端结论代替
