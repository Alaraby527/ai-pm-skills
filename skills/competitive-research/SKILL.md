# 竞品调研 Skill

## 简介

**干什么的**：系统性拆解竞品的产品功能、技术架构、商业策略与用户体验，输出可指导决策的结构化洞察。不是"列出竞品有哪些功能"，而是回答"为什么这样设计、我们该怎么应对"。

**核心方法论**：五层递进框架（L1 产品定位→L2 功能拆解→L3 技术架构→L4 商业策略→L5 用户体验）+ 三层竞品分类法 + 2C/2B 双路径深度测评 + SWOT + 战略象限 + 优先级三维评估。

**你能得到什么**：结构化竞品调研报告、竞品对比矩阵、技术壁垒评估、SWOT 分析、战略象限定位、交互设计六维度拆解、破局机会与优先级建议。

## 触发场景

当用户需要系统性了解某个产品、品类或赛道的竞争格局时触发。典型场景包括：
- 明确说「做竞品调研」「竞品分析」
- 要对比两个或多个产品的差异
- 想了解某款产品的能力水平、技术壁垒
- 进入新赛道前的竞争格局扫描
- 面试前的竞品分析准备

## 输入要求

**必需信息**：
- 调研目标（为什么做、决策用）：立项参考 / 功能对标 / 面试准备 / 战略分析
- 至少 1 个核心竞品名称或品类方向

**可选补充信息**：
- 己方产品/方案定位
- 关注的重点维度（功能 / 技术 / 定价 / 用户体验 等）
- 输出形式偏好（报告 / 表格 / 汇报用）

**信息不全时的追问话术**：
- 缺调研目标："这次竞品调研主要用于什么场景？是立项参考、功能对标，还是面试准备？不同目的我会调整分析深度和侧重点。"
- 只给了一个产品："除了 [产品名]，你有关注的直接竞品吗？如果没有，我可以根据赛道推荐 1-2 个对照组。"
- 缺己方定位："方便简单说下你们产品的定位吗？这样结论部分可以更有针对性地给启示。"

## 工作流（6 步）

### Step 1：明确调研目标与范围

- 确认调研目的：立项参考 / 功能对标 / 面试准备 / 战略分析
- 划定范围：直接竞品 / 间接竞品 / 潜在竞品 / 全赛道扫描
- 确定输出物形式和颗粒度
- **检查点**：向用户复述调研目标和范围，确认后再继续

**产出物检验**：用户确认的调研计划，含竞品清单、分析侧重点、输出形式、时间排期。调研目的不明确不进入下一步。

### Step 2：锁定竞品清单与信息采集

**2.1 竞品筛选（三层分类法）**：
1. **直接竞品**：同赛道、同目标用户、同类产品（如飞书 vs 钉钉），建议 2-3 个
2. **间接竞品**：解决同一问题但产品形态不同（如飞书 vs 企业微信），建议 1 个
3. **潜在竞品/标杆**：不同赛道但方法论可借鉴（如 Notion 的 AI 功能设计），建议 1 个

输出：竞品初选清单（3-5 个核心竞品，含入选理由）。只给一个产品时主动建议 1-2 个直接竞品做对照组。

**2.2 信息采集实操（每个竞品必做）**：
信息采集的完整度直接决定后续分析的天花板。这一阶段不追求深度判断，目标是把每个竞品"摸透摸全"。

1. **建立竞品信息卡**：每个竞品一张，记录产品名称、网站链接、所属公司、上线时间、目标用户、核心价值主张、盈利模式、竞品类型、入选理由、用户规模参考（10 字段，见 `references/template-competitor-info-card.md`）
2. **绘制网站结构图**：从首页开始逐一点击每个导航项和功能入口，记录所有一级导航、二级页面和关键功能入口的层级关系。**不要遗漏底部导航栏、侧边栏、弹窗内的功能入口**——很多核心功能藏在用户头像下拉菜单、底部链接区或浮动按钮中
3. **截图归档**：对每个关键页面截图，按统一命名规则归档（`竞品名_页面层级_页面名.png`）。需覆盖首页、所有一级导航页、核心操作流程页、注册/登录页、个人中心/设置页、**异常状态页（空数据、错误提示）**。每个竞品通常 15-30 张
4. **初步功能清单**：基于结构图整理，只记录"有什么"，先不评价好坏

**产出物检验**：每个竞品（含己方）都有完整信息卡（10 字段填全）+ 网站结构图（无遗漏导航入口）+ 15-30 张截图（含异常状态页）+ 初步功能清单。信息卡字段空缺超过 2 项需补充检索。

### Step 3：五层递进拆解（核心步骤，L3 为重点）

对每个竞品按五层框架逐层拆解，**L3 技术架构层篇幅最大、不得缺席**：

| 层级 | 分析维度 | 核心问题 | 产出物 |
|------|---------|---------|--------|
| **L1 产品定位** | 目标用户、核心场景、价值主张、商业模式 | 竞品为谁解决什么问题？ | 定位画布 |
| **L2 功能拆解** | 功能清单（穷举+分类）、交互流程、差异化功能 | 做了什么、怎么做的、哪些是独创？ | 功能对比矩阵 + 雷达图 |
| **L3 技术架构**（重点） | 模型/算法选型、数据 pipeline、RAG/Agent 架构、Prompt 策略、工程化方案 | 底层怎么实现的？技术护城河在哪？ | 技术架构对比表 |
| **L4 商业策略** | 商业模式、定价策略、增长路径、资源投入、市场份额 | 怎么赚钱、怎么增长？ | 策略象限图 |
| **L5 用户体验** | 交互设计六维度、用户流程、内容质量、响应速度、UI 风格 | 用户用起来感受如何？ | 交互拆解表 + 体验评分卡 |

**L2 功能拆解四步法**：
1. 穷举功能点：逐屏截图，记录可见功能 + 隐藏功能
2. 分类归组：按用户需求场景（而非页面位置）归组。标准分类框架（可按网站类型调整）：
   - **用户体系**：注册登录、个人资料、账号安全、权限管理
   - **核心业务**：因网站类型而异（商品浏览、内容发布、服务预约等）
   - **搜索与发现**：搜索、筛选、推荐、分类导航、热门排行
   - **互动与社交**：评论、点赞、收藏、分享、关注、私信
   - **交易与支付**：购物车、下单、支付、订单管理、退款
   - **通知与消息**：系统通知、互动消息、推送设置
   - **辅助功能**：帮助中心、反馈入口、设置、多语言、无障碍
3. 深度对比：不只比"有没有"，要比"做得怎么样"——用**实现程度三档**标注：
   - **完整**：功能完整可用，覆盖核心场景
   - **基础**：功能存在但能力有限，缺少高级选项
   - **缺失**：无此功能或仅有入口无实际功能
4. 差异化提炼：标注三个等级——核心差异（影响用户选择）、体验差异（影响满意度）、无差异

**功能深度打分标准（1-5 分，用于雷达图）**：
- 5 分：功能完整，有高级选项，覆盖多种场景，体验流畅
- 4 分：功能基本完整，个别高级选项缺失
- 3 分：核心功能可用，但功能广度或深度有明显不足
- 2 分：功能存在但仅停留在入口，可用性差
- 1 分：无此功能模块

**差距类型三分法**（用于功能差距清单）：
- **功能缺失**：竞品有而我们完全没有
- **深度不足**：功能存在但深度差距大（如只有基础版，竞品有高级选项）
- **体验落后**：功能存在、深度接近，但交互细节差

**L3 技术架构分析要求**：
- 区分【事实】（有公开资料确认）和【推测】（基于行业经验推断），严格标注
- 拿不到公开资料时，写"未找到公开信息"并给出基于行业惯例的推测，不得编造
- 外部可验证数据（估值、ARR、用户量）必须来自检索结果，附来源链接，不凭记忆编造

**L4 商业策略拆解方法**：
商业策略层回答"竞品怎么赚钱、怎么增长、投入多大"，从四个维度拆解：

1. **定价策略对比**：梳理各竞品的定价模式，制作定价对比表
   - 定价模式分类：免费 / 免费增值（Freemium）/ 订阅制 / 按量计费 / 定制报价 / 交易佣金 / 广告变现
   - 对比表字段：套餐名称、月/年价格、核心权益、限制条件（用量上限/功能锁/席位限制）、免费版边界
   - 注意：2B 产品常不公开定价，需标注"未公开，需联系销售"并从客户案例推断客单价区间

2. **增长路径分析**：
   - **获客渠道**：自然流量（SEO/内容营销/社区）、付费投放（SEM/信息流）、社交裂变（邀请/分享）、渠道合作（应用商店/平台分发）、品牌活动
   - **转化漏斗**：访问 → 注册 → 激活 → 留存 → 付费，标注各环节关键动作和可能的转化率
   - **留存机制**：会员体系、成长值/积分、内容更新频率、社区活跃度运营、推送/通知触达策略

3. **市场份额与资源投入**：
   - 用户量指标：MAU/DAU/注册用户数（附来源链接和数据时间，检索不到写"未找到公开信息"）
   - 融资历史与估值：轮次、金额、投资方、时间（附来源）
   - 团队规模与技术投入：从招聘信息、公开报道、LinkedIn 推断团队规模和技术栈投入

4. **数据来源说明**：优先使用 SimilarWeb（流量估算）、QuestMobile/艾瑞（移动数据）、公开财报、第三方行业报告、竞品官网定价页。不同来源数据冲突时并列展示，不擅自取舍。

**L5 用户体验——交互设计六维度拆解（重点补充）**：
功能分析关注"有什么"，交互分析关注"怎么用"。选择 3-5 个关键页面（高频页、核心转化页、已知痛点页、竞品差异显著页），按六维度逐一拆解"我们怎么做"和"竞品怎么做"：

| 维度 | 关注点 |
|------|--------|
| 信息架构 | 页面元素的组织方式、主次层级、视觉优先级 |
| 操作路径 | 完成核心任务需要几步操作、是否有快捷方式 |
| 反馈机制 | 操作后的即时反馈（loading、成功/失败提示、动画） |
| 引导与提示 | 首次使用引导、空状态提示、操作帮助文案 |
| 异常处理 | 错误状态处理、网络异常、数据为空时的表现 |
| 响应式适配 | 不同屏幕尺寸下的布局调整、移动端体验 |

同时选取 2-3 条核心用户流程做步数对比（如"搜索到完成查看详情"），每省一步用户到达目标的阻力就小一分。详细模板见 `references/template-interaction-analysis.md`。

> **交互分析红线**：最忌讳"看着不顺眼就记下来"。每条问题必须有竞品参照——如果所有竞品都没有你说的那个交互，那可能不是问题而是行业惯例；反过来，如果所有竞品都做了而你没做，那大概率是真问题。

**产出物检验**：五层分析全部完成（L1-L5 无缺席）；L3 技术架构每条都有【事实】/【推测】标注；L5 含交互六维度拆解表（3-5 个关键页面）；功能对比矩阵覆盖所有核心竞品，实现程度用完整/基础/缺失三档标注；L4 有定价对比表和增长路径分析。

### Step 4：深度测评（2C / 2B 两条路径）

**路径 A：2C 产品实测（5 步法）**
1. 注册走通完整新手流程
2. 核心功能全流程体验
3. 设计边界 case 测试模型能力
4. 同一问题/任务横向对比输出质量
5. 按能力等级评分（S/A/B/C）

**路径 B：2B 产品调研**
1. 官网 / 白皮书 / 客户案例梳理
2. 价格体系与套餐对比
3. 集成方式与开放能力分析
4. 行业解决方案覆盖度
5. 技术栈与合作伙伴推断

> 2C 实测无法执行时（如需邀请码、付费墙），降级为"基于公开信息的桌面分析"，并在报告中说明分析局限。

**产出物检验**：2C 产品有实测记录（含边界 case 测试结果）或桌面分析说明（含局限声明）；2B 产品有价格体系+客户案例（≥3个）+集成方式梳理；所有竞品完成能力等级评分（S/A/B/C）。

### Step 5：SWOT、战略象限与优先级评估

**SWOT 分析**：对核心竞品和己方产品分别做 SWOT（S 优势 / W 劣势 / O 机会 / T 威胁）。

**战略象限**：多产品时用 2×2 象限定位，坐标轴须说明选取理由（如 X 轴=技术深度，Y 轴=场景覆盖）。

**优先级三维评估模型**：将功能差距 + 交互问题合并后，按三个维度排序优先级（不是单纯看问题大小）：
- **用户影响度**：影响多少用户、对核心任务完成有多大阻碍（高频且阻碍核心流程 = 高）
- **竞争紧迫度**：该差距是否是竞品的核心卖点（竞品正以此差异化宣传 = 高）
- **实现成本**：修复需要多少研发资源（功能缺失通常成本高于交互优化）

三维综合后分四级：**P0（立即启动）、P1（下版本纳入）、P2（排入规划）、P3（持续观察）**。详细模板见 `references/template-priority-matrix.md`。

**产出物检验**：核心竞品和己方各有完整 SWOT（四项无空缺）；战略象限坐标轴有明确选取理由，每个产品有定位；优先级表覆盖 P0-P3 四级，每条问题都有三维评估（用户影响度/竞争紧迫度/实现成本）和建议动作。

### Step 6：输出调研报告与结论

按 `references/template-research-report.md` 模板输出，必须包含：
- 调研背景与目标
- 竞品选择与范围界定
- 五层分析结果（L1-L5 逐层展开，L3 不得缺席，L5 含交互六维度拆解）
- SWOT 与战略象限
- 综合对比矩阵（功能覆盖 + 功能深度 + 交互质量合并）
- 差异化需求清单（核心差异 → P0/P1/P2/P3 优先级建议，附三维评估）
- **结论与启示**：必须落到"对我们/对用户产品或求职有什么启示"，不少于 3 条，每条可执行
- 数据来源索引：所有外部数据附来源链接

**报告写作要点**：
- 核心结论写在报告最前面，不要让读者翻到最后才看到判断
- 每条结论必须有数据或截图支撑：❌"搜索体验落后"不是结论；✅"搜索结果页无筛选条件，竞品 A 支持 5 种筛选维度，用户找到目标平均多花 40 秒"才是结论
- 建议具体到页面和功能模块，不出现"提升用户体验""优化交互流程"等无法执行的表述

**产出物检验**：报告含 8 个必需章节（背景→竞品选择→五层分析→SWOT→战略象限→综合矩阵→差异化清单→结论启示→数据来源）；数据来源索引完整（每条外部数据有链接+时间）；结论与启示≥3 条且每条可执行（具体到页面/功能/动作）；L3 技术架构层无缺席、无一句话带过。

## 质量红线

1. **L3 技术架构层不得缺席、不得一句话带过**。拿不到公开资料时写【推测】与【事实】严格区分，不得编造技术细节。
2. **外部可验证数字必须来自检索结果并附来源链接**（估值、ARR、用户量、融资额等），不凭记忆编造。检索不到写"未找到公开信息"。
3. **结论必须有"对自己产品/求职的启示"**，纯罗列竞品信息不合格。启示不少于 3 条，每条可执行。
4. **不得只比功能不做洞察**：列出功能点后必须提炼"为什么这样设计"和"我们该怎么应对"。
5. **多产品对比必须有横向对比矩阵**，不能逐个描述完就结束。
6. **数据可追溯**：每一条结论都有对应的数据来源——截图、操作录屏、或可复现的操作路径。"感觉""大概""可能"不出现在结论中。
7. **对比有参照**：每一条问题都有至少一个竞品作为参照。没有参照的"问题"不纳入报告——可能是行业惯例而非缺陷。
8. **结论有优先级**：所有发现按 P0-P3 排序，不平等罗列。读者应能从优先级表直接读出"先做什么"。
9. **建议可落地**：优化建议具体到页面和功能模块，不出现无法执行的空泛表述。

## 常见误区

| 误区 | 正确做法 |
|------|---------|
| 选择流量极大但业务模式差异过大的产品作为直接竞品（如垂直电商把综合电商巨头当直接竞品） | 直接竞品找同品类、同用户规模的；标杆竞品可跨品类，但仅用于交互/功能模式参考 |
| 信息采集只看顶部导航，遗漏底部栏、侧边栏、弹窗内的功能入口 | 逐一点击所有入口，直到找不到新页面为止 |
| 截图只覆盖正常流程，遗漏异常状态页（空数据、错误提示） | 异常状态必须覆盖，这往往是体验差距最大的地方 |
| 功能对比只标"有/无"，不评估实现深度 | 用完整/基础/缺失三档 + 1-5 分深度打分 |
| 交互分析"看着不顺眼就记下来"，没有竞品参照 | 每条问题必须有竞品参照；所有竞品都没有的可能是行业惯例 |
| 优先级只看问题大小，不考虑影响用户数和实现成本 | 用用户影响度×竞争紧迫度×实现成本三维评估 |
| 报告把结论藏在最后，前面全是数据罗列 | 核心结论写最前面，每条有数据支撑 |
| L4 商业策略只写"免费/收费"，不拆解定价细节和增长路径 | 制作定价对比表（套餐/价格/权益/限制），分析获客→转化→留存全链路 |

## 异常兜底

| 异常情况 | 处理方式 |
|---------|---------|
| 找不到竞品公开信息 | 标注"未找到公开信息"，基于行业惯例给出【推测】并说明推测依据，不编造 |
| 2C 产品无法注册实测（邀请码/付费墙） | 降级为桌面分析（官网+评测+用户评论），在报告中说明分析局限 |
| 用户只给了模糊方向（如"AI 教育赛道"） | 先给出赛道玩家分类表，让用户选择重点分析对象，不盲目展开 |
| 竞品数量过多（>8 个） | 按三层分类法筛选 3-5 个核心竞品深度分析，其余列入全景图简表 |
| 信息冲突（不同来源数据不一致） | 并列展示不同来源的数据，标注来源和时间，不擅自取舍 |
| 检索工具/API 调用失败 | 重试 1 次（缩小范围/减少 page size），仍失败则降级为基于已有信息的分析，报告中标注"数据获取受限" |
| 用户中途改变调研范围 | 重新执行 Step 1 确认新范围，保留已采集的信息不丢弃，调整后续步骤 |
