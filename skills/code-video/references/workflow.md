# 六步工作流

出片质量 90% 由前三步决定，后三步只是把已经想清楚的东西落成像素。不要跳过 1-3 直接写代码。

## 0. 需求归一（30 秒内做完）

把用户的一句话拆成六个槽位，缺哪个就问哪个，一次问完：

| 槽位 | 为什么必须先定 |
|---|---|
| 题材 + 受众 | 决定信息密度和用词，专业内容要科普化 |
| 时长 | 决定场景数量，默认按「每场景 4-8 秒」估 |
| 画幅 | 16:9 (1920×1080) / 9:16 (1080×1920) / 1:1 |
| 语言 | 中文为主时字号要大 1 档，行高 1.7 以上 |
| 音轨 | 有没有旁白/音乐，直接决定时间轴对齐方式 |
| 用途 | 发布平台（抖音/视频号/B站/官网）决定安全区与首帧钩子 |

## 1. 知识稿：先有事实，再谈画面

产出**事实卡片**而不是散文。每张卡片四行：

```
主张：图灵测试的核心是行为不可区分，不是"机器是否真的会思考"
可视化为：三节点关系图（人 / 文字通道 / 机器）
出处：Turing 1950, Mind, "Computing Machinery and Intelligence"
风险：易被误解为"AI 已通过测试"，需一句限定
```

规则：

- 每条主张必须有出处，没有出处的不写进片子。
- 先问「这句能不能被画出来」。画不出来的，压缩成一句旁白或直接删。
- 一张卡片对应屏幕上最多 12 个字。超过就说明这一屏塞多了。
- 数字必须可核验（年份、参数、比例）。视频里说错数字是最贵的错误，因为改要重渲染。

## 2. 分镜表：唯一的真相来源

渲染代码是分镜表的实现，不是创作现场。先写表，再写代码。

| # | 入点(s) | 出点(s) | 屏幕文字 | 旁白 | 视觉模式 | 素材 |
|---|---|---|---|---|---|---|
| 1 | 0 | 4 | 一句话，变成一条片子 | 无 | 大标题 | 无 |
| 2 | 4 | 8 | 把论点拆成看得见的结构 | 结构先立住 | 关系图 | 3 个 SVG 节点 |
| 3 | 8 | 12 | “能讲清楚，是因为结构先立住了。” | 风格是外壳 | 引文 | 无 |

硬规则：

- 场景时长必须是**整数秒**的倍数，落到帧上才整齐（30fps 下 4s = 120 帧）。
- 每屏只讲一件事。要讲两件事就拆两屏。
- 转场时间单独留 0.4-0.5s，不要叠在内容时长里。
- 全片场景数建议 3-8 个。超过 10 个就该考虑拆成系列。

## 3. 视觉系统：先定令牌，再定样图

顺序不能反：

1. 选一套主题令牌（见 `visual-system.md`，深色知识 / 浅色编辑 / 品牌定制）。
2. 把令牌写进代码的单一位置（HyperFrames 放 `:root` CSS 变量，Remotion 放 `theme.ts`）。
3. **先出一张静态风格样图**（一个场景、一帧），确认后再批量做。
4. 确认的点只有四个：底色对不对、字体气质对不对、主色强调比例、信息密度。

这一步是返工成本的分水岭。跳过样图直接做全片，十有八九要重来。

## 4. 素材：分级处理

| 类型 | 做法 | 注意 |
|---|---|---|
| 图标 / 流程图 / 关系图 | 用 SVG 或 DOM 画 | 永远清晰，可动画，优先 |
| 照片 / 人物 | AI 生成或图库，落成本地文件 | 别在渲染时拉远程图，会拍到空白帧 |
| 数据图表 | 用库（D3 / 手写 SVG） | 数字要来自事实卡片，不要现编 |
| 音频 | 本地 mp3/wav，先量出时长再排场景 | 时长以音频为准，不要以脚本为准 |

素材清单里每一项写：文件名、尺寸、放哪个场景、是否要动。没有清单就会边做边找，最后风格不统一。

## 5. 样片：只做最难的那 10-20 秒

不要按顺序做前 20 秒。挑**信息最密、动效最复杂**的那一屏先做，因为它决定整片的技术上限。

样片验收三个问题：

1. 照着看不看得到重点？（眶眼测试）
2. 文字有没有溢出、换行难看、贴边？
3. 动效是「帮理解」还是「在炫技」？

满意了再铺开。不满意就改令牌和结构，不要在单屏上反复微调细节。

## 6. 全片 + 验收

渲染全片后必须抽帧自检，不能只看渲染日志成功。

```bash
python3 scripts/render.py <工程目录> -q delivery --stills 1.5,6.5,10.5
```

逐项核对：

- [ ] `lint` / `check` 无 error
- [ ] 时长与分镜表一致（±0.1s）
- [ ] 分辨率、帧率与需求一致
- [ ] 每屏首帧和末帧文字都在安全区内（左右上下各留 96px）
- [ ] 中文字形正确，没有 fallback 字体（宋体被替换成黑体最常见）
- [ ] 深色背景下正文对比度足够（灰字不要低于 `#8C9099`）
- [ ] 有音频时，人声与字幕对齐，结尾不截断
- [ ] 首 3 秒有钩子，末 3 秒有落点

# 提示词骨架

给编码 Agent 的提示词，必须把**工程约束**写进去，否则它会按「写网页动画」的习惯写 `setTimeout`，渲染出来全是静止帧。

## A. 环境初始化

```
在当前目录配置 HyperFrames 视频工程（或 Remotion）。
按官方文档补齐依赖，跑通一个 5 秒测试视频，确认能出 MP4，然后告诉我预览和渲染命令。
不要修改我已有的其他文件。缺什么自己补，补不了再告诉我。
```

## B. 分镜编排（给参考片时用）

```
我要做一条 {时长} 秒的 {题材} 视频，面向 {受众}，{画幅}。

参考这两条片的组织方式：{参考链接/截图}
参考它们的节奏和结构，不要抄内容。

输出一张分镜表，字段：序号 / 入点 / 出点 / 屏幕文字 / 旁白 / 视觉模式 / 素材。
约束：
- 每屏只讲一件事，屏幕文字 ≤ 12 字
- 场景时长取整数秒
- 每 2-3 个场景要有一次视觉节奏变化（图 → 字 → 图）
```

## C. 单场景实现

```
按分镜表第 {n} 屏实现画面。

视觉令牌：{贴入 tokens，或指向 theme 文件}
硬性约束：
- 动画必须由时间轴/帧号显式计算，禁止 setTimeout、requestAnimationFrame、CSS transition/keyframes
- 时间轴保持 paused，由框架驱动
- 字体必须显式加载完成后再渲染
- 文字、图表用 DOM/SVG，不要贴图
- 所有素材用本地相对路径
完成后跑 lint，报 0 error 再给我。
```

## D. 返工修正

```
第 {n} 屏的问题：{具体描述，如"标题第二行掉出了安全区"}。
只改这一屏，不要动其他场景的时间轴。
改完重新抽帧给我看 {时间点} 的画面。
```

# 常见失败模式

| 现象 | 根因 | 处置 |
|---|---|---|
| 渲染出来全静止 | 用了实时动画 API | 改成时间轴/帧函数 |
| 只有第一帧有字，后面空白 | 字体没加载完就截图 | `delayRender` / 等 `document.fonts` |
| 中文字体被替换 | 令牌写了系统字体但渲染环境没有 | 用 Google Fonts 或自托管 woff2 |
| 图片是空白框 | 远程图片没等到加载 | 下载到本地，或加加载闸门 |
| 时长差几帧 | 场景时长不是整秒 | 全部对齐到 `n * fps` |
| 越改越乱 | 没有分镜表，边做边想 | 退回第 2 步 |
