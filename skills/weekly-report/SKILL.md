# 周报助手

## 目标

将用户一周的工作记录、聊天摘录、任务清单或口述内容，整理成简洁、直观、可直接发送的中文工作周报。以「数据指标变化」为主线，一张表格呈现本周工作进度、对应的数据提升和卡点问题，再补一段改进方法与下周计划。不写流水账，不堆砌任务数量，篇幅控制在一次阅读能抓住重点的程度。

## 适用场景

以下需求适用本 Skill：

- 帮我写这周的周报
- 整理本周工作进展
- 把这些工作记录整理成周报
- 生成一份本周工作汇报
- 汇总本周完成的事项、指标变化、卡点和下周计划

不适用于日报、月报、季度述职或正式绩效总结；用户明确要求这些类型时，按用户要求处理，不强行套用本模板。

## 输出原则（先读）

1. **一张表格为主**：周报主体是一张表，列名固定为「本周工作 / 进度｜对应数据指标变化｜卡点问题」。每行一个工作主题。
2. **只写指标提升**：数据列只放可验证的指标变化，如转化率、覆盖率、耗时、准确率、留存、GMV、点击率等；**不写**“完成 X 个任务”“产出 X 份文档”这类数量统计。
3. **数据为主、过程从简**：能用一个数字说明的不用一句话；无数据时用克制的定性表达或标「待补充」，不编造数字。
4. **不冗长**：表格行数控制在 3～6 行；每格一句话以内；没有内容写「暂无」或「待补充」，不留空白长文。
5. **改进在表下、计划在最后**：表格之后是一段「改进方法」，最后是「下周计划」。

## 输入信息

### 必需信息

至少提供以下任意一类信息：

- 本周推进的工作及当前进度
- 工作对应的指标或数据变化（可选，缺省按“待补充”处理）
- 本周遇到的卡点或问题
- 下一步计划或改进想法

### 可选信息

- 周次或日期范围（如“本周 10.14–10.18”）
- 指标名称与具体数值、趋势（如“环比 +8%”“由 62% 升至 70%”）
- 卡点原因、影响范围与当前状态
- 需要支持的对象或资源
- 改进方法的思路
- 输出风格，如精简版、正式版、群聊版、领导汇报版

### 默认处理

- 未提供周次/日期：使用当前本地日期所在周，标注「本周（YYYY年M月D日–M月D日）」。
- 未提供数据：对应格写「待补充」，不补造数字。
- 未提供某列内容：写「暂无」或「待补充」。

## 工作流程

1. **提取事实**
   - 提取本周工作主题、进度、指标变化、卡点问题、改进想法和下周计划。
   - 产出：事实清单，不添加用户未提供的结论。

2. **归类到表**
   - 把信息归入三列：本周工作/进度、对应数据指标变化、卡点问题。
   - 合并同类工作主题，删除重复描述和无关过程。
   - 只保留指标提升类数据；任务数、产出物数量等统计一律不进入数据列。
   - 产出：按主题对齐的一张大表。

3. **提炼数据**
   - 把分散的数字整理成“指标 + 变化 + 数值”的紧凑表达，如“漏斗转化率 62%→70%”。
   - 无量化数据的格子写「待补充」，不臆造。
   - 产出：数据列可读、可验证。

4. **写改进方法**
   - 基于卡点和数据不足，写一段针对性的改进方法（1～3 条，每条约一句话）。
   - 改进必须可执行，不写空泛口号。
   - 产出：表格下方的一段改进方法。

5. **列下周计划**
   - 用清单列出下周 3～5 项计划，每项含可检验的下一步动作。
   - 产出：下周计划清单。

6. **输出检查**
   - 检查表格列是否完整、数据是否只含指标提升、是否无冗长无流水账、改进方法是否可执行。
   - 产出：可直接发送的周报。

## 标准输出结构

```markdown
# 工作周报

**周期：** 本周（YYYY年M月D日–M月D日）

## 一、本周工作

| 本周工作 / 进度 | 对应数据指标变化 | 卡点问题 |
|---|---|---|
| 例：上线推荐位改版，已完成全量灰度 | 点击率 3.2%→4.1%（+28%） | 无 |
| 例：优化报表导出链路 | 导出耗时 45s→12s | 依赖方接口延迟待确认 |
| 例：完善异常监控告警 | 线上告警误报率下降 30% | 部分告警阈值需人工校准 |

## 二、改进方法

- 针对卡点：……（可执行的一步）
- 针对数据：……（补测/埋点/口径统一）
- 针对流程：……（固化 SOP / 加评审）

## 三、下周计划

- [ ] ……
- [ ] ……
```

## 指标表达的写法

- 优先「指标 + 变化 + 数值」：`转化率 62%→70%`、`耗时 45s→12s`、`覆盖率 55%→80%`。
- 有环比/同比时补充方向：`环比 +8%`、`同比持平`。
- 数据口径尽量明确：`日活`、`7日留存`、`付费转化`，避免裸写百分比。
- 指标与本周工作严格对应；一个指标不能归属多个不相关的工作主题。
- 只有目标值没有实际值时写「目标 X，实际待补充」。

## 改进方法的写法

- 每一条对应一个卡点或数据短板，先点问题再给动作。
- 用“通过……实现……”或“针对……，计划……”的可执行句式。
- 改进方法控制在 1～3 条，长度一句话；没有改进点时写「暂无」。

## 下周计划的写法

- 每项计划是下一步动作，不是愿望，如「完成 A/B 实验二期样本收集」。
- 优先排与本周卡点、数据短板相关的项。
- 计划 3～5 项；不足时写「待补充」。

## 异常兜底

| 异常情况 | 处理方式 |
|---|---|
| 没有任何工作内容 | 追问本周完成、指标变化、卡点问题与下周计划；用户暂不补充时不编造周报 |
| 只有零散关键词 | 按工作主题归表生成可用草稿，并标记待补充信息 |
| 内容重复 | 合并同类工作主题，保留进度、数据变化和卡点 |
| 信息相互冲突 | 标记冲突点，保留不确定性，不擅自选择结论 |
| 缺少指标数据 | 数据列写「待补充」，不补造数字 |
| 数据只有数量没有指标 | 数量统计不进数据列，按「暂无指标」处理 |
| 有问题但暂无解决方案 | 卡点列写明当前状态和影响，把解决方案列入改进方法或下周计划 |
| 缺少下周计划 | 写「具体安排待补充」，不擅自推测 |
| 用户要求压缩篇幅 | 表格只保留 3 行以内核心工作，改进方法合并为 1 条，计划保留 3 项 |

## 交互方式

- 用户提供完整一周记录时，直接输出最终周报。
- 用户提供碎片化记录时，先按工作主题归表，再输出可用草稿。
- 用户只说“帮我写周报”但没有工作内容时，使用最少追问：本周做了什么、对应指标有什么变化、遇到什么卡点、下周计划什么。
- 用户要求“更简短”“更正式”“适合发群里”“适合汇报领导”时，只调整篇幅、语气和表达，不改变事实。
- 用户希望把某些行从表格里拆出来详述时，可单独展开，但保持整体以表格为主。

## 输出前自检

- 表格列完整：本周工作/进度、对应数据指标变化、卡点问题三列齐全。
- 数据列只含指标提升类数据，无任务数、产出物数量等统计。
- 每格一句话以内，表格行数 3～6 行，无冗长流水账。
- 未虚构指标、数值、原因、支持人或截止时间。
- 改进方法可执行，下周计划是下一步动作。
- 周期标注准确。
