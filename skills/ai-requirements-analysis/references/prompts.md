# AI 需求分析提示词合集

## 1. 需求澄清阶段

### 1.1 AI 需求四问澄清提示词

```
我有一个 AI 产品想法：【描述你的想法，越详细越好】

请用 AI 需求四问法帮我澄清这个需求：

1. 用户是谁？
   - 目标用户画像（角色、行业、痛点）
   - 有几类用户？谁是核心用户？
   
2. 什么场景下触发？
   - 典型使用场景
   - 触发条件
   - 使用频率
   
3. 当前怎么解决的？
   - 现有方案
   - 现有方案的痛点
   - 替代方案对比

4. AI 能解决吗？
   - AI 在这个需求里的角色
   - 哪些 AI 能做，哪些不能
   - 做不到时怎么兜底

请尽量具体，不要空泛。如果信息不足，请指出我需要补充什么。

【业务背景补充：】
```

### 1.2 需求拆解提示词

```
这是一个 AI 产品需求：【需求描述】

请帮我把这个需求拆解成：
1. 用户痛点列表（至少 5 个，按严重程度排序）
2. 功能点列表（对应每个痛点的解决方案）
3. 优先级排序（P0/P1/P2）及判断理由
4. MVP 版本应该做什么、不做什么
5. 成功标准（怎么判断这个需求做对了）
```

## 2. 可行性评估阶段

### 2.1 技术可行性分析提示词

```
我想做一个 AI 功能：【功能描述】

请帮我做技术可行性分析：

1. 模型能力评估
   - 当前主流大模型（GPT-4、Claude、文心、通义等）能做到吗？
   - 准确率/效果大概能到什么水平？
   - 有哪些已知的能力边界？

2. 技术路线选择
   - 纯 Prompt 工程能实现吗？
   - 是否需要 RAG？为什么？
   - 是否需要微调？为什么？
   - 是否需要自研模型？为什么？
   - 推荐技术路线及理由

3. 数据需求
   - 需要什么数据？
   - 数据从哪里来？
   - 数据获取难度如何？

4. 实现复杂度
   - 预估开发周期
   - 需要什么角色的人
   - 主要技术难点

5. 风险点
   - 最大的技术风险是什么？
   - 怎么规避或验证？

我的背景：【描述你的技术资源/团队情况】
```

### 2.2 成本可行性分析提示词

```
【功能描述】这个 AI 功能，请帮我估算成本：

1. 开发成本
   - 需要什么技术角色
   - 预估人天
   - 总成本估算

2. 运行成本
   - 单次调用成本（Token 估算）
   - 假设日活 X，月度成本估算
   - 成本优化空间（缓存、模型分层等）

3. 投入产出比
   - 对比纯人工方案的成本
   - 多久能回本
   - ROI 估算

4. 不同方案的成本对比
   - 方案 A（纯 Prompt）
   - 方案 B（RAG）
   - 方案 C（微调）
```

### 2.3 合规风险评估提示词

```
【AI 功能/产品描述】

请帮我评估这个 AI 产品的合规风险：

1. 数据隐私风险
   - 涉及哪些用户数据？
   - 是否需要用户授权？
   - 数据能不能用于模型训练？
   - 跨境数据传输问题？

2. 内容安全风险
   - 可能生成哪些有害内容？
   - 风险等级（高/中/低）
   - 如何防范？

3. 行业监管
   - 【行业】有哪些特殊的监管要求？
   - AI 相关的政策法规影响？

4. 伦理风险
   - 可能存在哪些偏见/歧视问题？
   - 透明度问题（用户知不知道是 AI？）
   - 责任归属问题

5. 风险应对建议
```

## 3. 方案设计阶段

### 3.1 AI 参与模式选择提示词

```
【产品/功能描述】

请帮我判断这个 AI 功能应该用哪种参与模式：

模式选项：
1. Copilot 辅助模式 —— AI 出草稿/建议，人工最终确认
2. Agent 自主模式 —— AI 自动完成全流程，自主决策
3. 插件工具模式 —— AI 仅作为单一环节嵌入业务流程

请分析：
1. 每种模式的适用情况
2. 推荐哪种模式？为什么？
3. 如果选 Copilot，AI 和人的分工边界是什么？
4. 如果选 Agent，异常兜底方案是什么？
5. 如果选插件，嵌入哪个环节？上下游是什么？

判断维度建议：错误成本、用户预期、自动化程度、技术成熟度
```

### 3.2 MVP 方案设计提示词

```
【产品/需求描述】

我想做 MVP 版本，请帮我规划：

1. MVP 的核心目标是什么？（验证什么假设？）
2. MVP 必须有的 3 个核心功能
3. MVP 可以没有的功能（即使很想要也先砍掉）
4. MVP 的最简实现路径
   - 能不能用现成工具（Coze/Dify 等）先搭？
   - 哪些可以用人工替代？
   - 最快多久能上线？

5. MVP 的成功标准
   - 看什么指标？
   - 达到什么数值算成功？
   - 验证周期多长？

6. MVP 之后的迭代路线图
   - V1.0 → V1.1 → V2.0 各加什么
```

### 3.3 Prompt 方案设计提示词

```
我需要为【功能场景】设计 Prompt。

功能描述：
【详细描述这个 AI 功能做什么、输入什么、输出什么】

请帮我设计：
1. Prompt 整体框架
   - 角色设定
   - 任务指令
   - 输入格式
   - 输出格式
   - 约束条件

2. 第一版完整 Prompt

3. 测试这个 Prompt 可能遇到的问题
   - 哪些情况可能输出不符合预期？
   - 如何优化？

4. 如果效果不好，优化方向有哪些？
```

## 4. 文档输出阶段

### 4.1 PRD 生成提示词

```
请帮我把以下需求整理成一份完整的 AI 产品 PRD：

【需求背景：】
【目标用户：】
【核心功能：】
【技术方案：】
【验收标准：】

按照标准 AI PRD 模板输出，包含：
1. 背景与目标（业务背景、为什么用大模型解决、竞品分析、产品目标）
2. 需求描述（需求清单、功能/性能/安全/数据需求分类）
3. 场景与流程（用户场景、业务流程图、系统流程图）
4. AI 优化方案（参与模式、技术路线、模型选型、Prompt 工程设计）
5. 评测体系（评测集构建方法、评分标准、执行流程）
6. 效果保障与稳定性（输出质量控制、幻觉治理、稳定性工程）
7. 评估指标（3D 验收指标）
8. AI 能力边界说明
9. 数据飞轮与迭代机制
10. 上线与运营（灰度发布、成本监控、回滚方案）
11. 风险与合规

要求专业、具体、可执行。
```

## 5. 模型选型阶段

### 5.1 模型选型对比提示词

```
我需要为【功能场景】选择合适的大模型，请帮我做模型选型分析：

功能描述：
【详细描述这个 AI 功能做什么、输入什么、输出什么】

约束条件：
- 成本约束：单次调用成本 ≤ ¥__
- 延迟约束：P95 ≤ __秒
- 合规约束：数据不出境/可私有化部署
- 效果要求：评测集得分 ≥ __分

请帮我：
1. 列出 3-5 个候选模型（覆盖不同参数规模和厂商）
2. 从以下维度对比：
   - 效果水平（公开 benchmark / 类似场景案例）
   - 调用成本（输入/输出每千 token 价格）
   - 延迟表现（首 token 时间 / 总生成时间）
   - 部署方式（API / 私有化 / 端侧）
   - 上下文长度
   - 多模态能力（如需要）
3. 给出推荐结论：
   - 主模型推荐及理由
   - 备用模型（failover 方案）
   - 成本预估（日均/月均调用量下的费用）
4. 选型理由：为什么这个场景选这个模型，而不是其他

核心原则：从小参数模型开始验证，效果相似时优先使用小参数模型（成本低）。
```

## 6. Prompt 工程设计阶段

### 6.1 System Prompt 设计提示词

```
我需要为【功能场景】设计 System Prompt，请帮我：

功能描述：
【详细描述这个 AI 功能做什么、输入什么、输出什么】

请设计：
1. 角色定义：模型扮演什么角色、具备什么能力边界
2. 输出约束：
   - 格式要求（JSON/Markdown/纯文本）
   - 长度限制
   - 语言风格
   - 禁止输出的内容
3. 核心指令：完成任务的关键指令逻辑（分步/分步骤）
4. 示例（少样本示例，2-3 个）

输出完整的 System Prompt 文本。

要求：
- Prompt 必须可直接投入使用，不要留占位符
- 约束规则要具体、可执行，不要模糊表述
- 考虑常见的失败 case，提前在 Prompt 中规避
```

### 6.2 Prompt 优化提示词

```
我有一个 Prompt，效果不太好，请帮我优化：

当前 Prompt：
【粘贴你的 Prompt】

问题现象：
【描述具体问题，比如：输出格式不对/ hallucination 严重/ 不按要求执行/ 太长了】

输入样例：
【给 1-2 个典型输入】

输出样例（当前效果）：
【给 1-2 个当前输出】

期望效果：
【描述你想要的输出是什么样的】

请帮我：
1. 分析当前 Prompt 的问题所在
2. 给出优化后的完整 Prompt
3. 说明优化点和预期改进效果
```

## 7. 评测体系设计阶段

### 7.1 评测集构建提示词

```
我需要为【功能场景】构建评测集，请帮我设计：

功能描述：
【详细描述这个 AI 功能做什么、输入什么、输出什么】

请帮我设计：
1. 数据来源规划（线上真实 query / Bad Case / 人工构造 / 公开数据集，各占比多少）
2. 覆盖度设计（按场景分层，核心场景/边缘场景/极端 case 各占多少比例）
3. 规模标准（上线前全量多少条，核心子集多少条）
4. 设计 10 条示例评测用例（覆盖不同场景类型）
   - 每条包含：输入、期望输出、评分要点
5. 标签体系（每条用例需要标注哪些维度的标签）

要求：
- 评测集要贴近真实使用场景，不要都是"完美输入"
- 必须包含一定比例的边界 case 和 bad case
- 评分要点要具体、可操作，标注人员能看懂
```

### 7.2 评测评分标准设计提示词

```
我需要为【功能场景】设计评测评分标准，请帮我：

功能描述：
【详细描述这个 AI 功能做什么、输入什么、输出什么】

请帮我设计：
1. 评测维度（3-6 个维度，覆盖效果、质量、合规等）
2. 每个维度的评分标准（1分/3分/5分分别是什么样的）
3. 权重分配（每个维度占总分的比例）
4. 一票否决项（哪些问题直接判不合格）
5. 总分计算方式和达标线

要求：
- 评分标准要具体、可操作，不要模糊的"好/不好"
- 每个分数档要有明确的判断依据
- 考虑实际场景中最常见的失败模式
```

### 7.3 幻觉治理方案提示词

```
我的 AI 产品有幻觉问题，请帮我设计幻觉治理方案：

功能场景：
【描述这个 AI 功能做什么】

幻觉表现：
【描述具体的幻觉问题，比如：编造不存在的事实/ 引用错误的来源/ 捏造数据等】

当前技术方案：
【描述现在用的是什么技术，纯 Prompt / RAG / 微调等】

请帮我：
1. 分析幻觉产生的可能原因
2. 设计多层级的幻觉治理方案：
   - 输入层（Prompt 约束、事实来源限制）
   - 生成层（RAG 增强、检索 grounding、引用标注）
   - 输出层（事实校验、置信度阈值、矛盾检测）
3. 各方案的预期效果和实施成本对比
4. 推荐的落地优先级（先做哪个，后做哪个）
5. 如何验证幻觉治理的效果（评测指标）
```
