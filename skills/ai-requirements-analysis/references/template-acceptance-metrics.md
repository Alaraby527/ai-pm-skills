# 3D 验收指标与评测体系模板

## 一、3D 指标设计方法

每个核心指标必须包含三个要素：

| 要素 | 含义 | 示例 |
|------|------|------|
| **Dimension（维度）** | 衡量什么 | 准确率、召回率、满意度、人工干预率、转化率 |
| **Degree（程度）** | 目标值 | 准确率 ≥ 92%、满意度 ≥ 85%、人工干预率 ≤ 10% |
| **Duration（周期）** | 达标时间 | 上线 3 个月内、灰度 2 周后 |

---

## 二、指标分类

### 效果指标（AI 输出质量）

| 指标 | 定义 | 目标值 | 周期 | 测量方式 |
|------|------|--------|------|---------|
| 准确率 | AI 输出正确的比例 | ≥ __% | | 评测集/人工标注 |
| 幻觉率 | AI 编造信息的比例 | ≤ __% | | 事实一致性检测 |
| 召回率 | 应返回结果中实际返回的比例 | ≥ __% | | 评测集对比 |
| 忠实度 | RAG 回答基于上下文的比例 | ≥ __% | | 回答与检索内容一致性 |
| 拒答率 | AI 拒绝回答的比例 | ≤ __% | | 日志统计 |

### 业务指标（商业价值）

| 指标 | 定义 | 目标值 | 周期 | 测量方式 |
|------|------|--------|------|---------|
| 转化率 | | ≥ __% | | 漏斗埋点 |
| 成本降低 | | 降低 __% | | 前后对比 |
| 收入增量 | | | | AB 测试 |
| 人工替代率 | AI 替代人工的比例 | ≥ __% | | 工单/任务统计 |

### 体验指标（用户感受）

| 指标 | 定义 | 目标值 | 周期 | 测量方式 |
|------|------|--------|------|---------|
| 采纳率 | 用户采纳 AI 输出的比例 | ≥ __% | | 采用/复制埋点 |
| 人工干预率 | AI 输出被修改的比例 | ≤ __% | | 修改行为埋点 |
| 任务完成率 | 用户成功完成目标任务的比例 | ≥ __% | | 任务埋点 |
| 响应时长 | P95 响应时间 | ≤ __ 秒 | 上线时 | 性能监控 |
| 满意度 | 用户主观评分 | ≥ __/5 | | 评分弹窗/问卷 |

---

## 三、指标设定注意事项

1. **目标值要有依据**：参考行业 benchmark、历史数据或竞品水平，不拍脑袋
2. **指标之间可能冲突**：如准确率 vs 覆盖率，需明确优先级
3. **护栏指标**：优化核心指标时监控护栏指标（如优化点击率时监控退货率）
4. **分阶段目标**：MVP 阶段目标可以低一些，随迭代逐步提升
5. **可测量性**：每个指标必须有明确的测量方式和数据来源，无法测量的指标不写

## 四、评测集构建方法论

> 评测集是 AI 产品最核心的资产之一。一个 AI 产品 PM 的专业程度，很大程度上体现在构建评测集的能力上。

### 4.1 数据来源

| 来源 | 采集方式 | 占比建议 |
|------|---------|---------|
| 线上真实 query | 从生产环境采样，按流量分布分层 | 50%-60% |
| 用户反馈 Bad Case | 用户点踩/差评/投诉的案例 | 15%-20% |
| 人工构造 | 针对边界场景、极端 case 专门设计 | 15%-20% |
| 公开数据集 | 行业公开 benchmark 或标准测试集 | 5%-10% |

### 4.2 覆盖度设计（按场景分层）

| 场景层级 | query 类型 | 预期占比 | 说明 |
|----------|-----------|---------|------|
| 核心场景 | 高频、主要功能路径 | 60%-70% | 覆盖 80% 以上用户使用场景 |
| 边缘场景 | 低频、但用户期望能处理 | 20%-25% | 保证体验一致性 |
| 极端 case | 输入异常、边界条件、对抗样本 | 5%-10% | 测试鲁棒性和兜底能力 |

> 关键原则：评测集各类 query 的比例要尽量贴近上线后的真实比例，避免"考试重点和实际考的不一样"。

### 4.3 规模标准

| 阶段 | 最少用例数 | 说明 |
|------|-----------|------|
| 上线前全量评测集 | ≥ 200-500 条 | 按场景复杂度调整 |
| 核心子集（回归测试用） | ≥ 50 条 | Prompt 变更时必跑，快速验证不引入新问题 |
| 每季度新增 Bad Case | ≥ 30 条 | 持续扩充评测集 |

## 五、评测维度与评分标准

> 不同产品类型的评测维度不同，以下为通用框架，需根据实际场景裁剪。

| 维度 | 分值 | 1分（差） | 3分（及格） | 5分（优秀） |
|------|------|-----------|-------------|-------------|
| 准确性 | 0-5 | 事实错误、答非所问 | 基本正确，有小瑕疵 | 完全准确，信息丰富 |
| 完整性 | 0-5 | 严重遗漏关键信息 | 覆盖主要信息 | 全面覆盖，逻辑完整 |
| 格式规范 | 0-5 | 格式混乱，不可用 | 基本符合格式要求 | 格式标准，开箱即用 |
| 安全合规 | 0-5 | 出现违规/敏感内容 | 无违规内容 | 主动规避风险 |
| 表达质量 | 0-5 | 语句不通，难以理解 | 表达清晰流畅 | 语言优美，超出预期 |

### 评分机制示例（可根据场景自定义权重）：

- 总分 = 准确性×30% + 完整性×25% + 格式规范×15% + 安全合规×20% + 表达质量×10%
- **安全合规为一票否决项**：该维度 ≤ 2 分，无论总分多少，判定为不通过

## 六、评测执行流程

### 6.1 评测方式

| 评测方式 | 说明 | 适用场景 |
|---------|------|---------|
| 人工评测 | 标注人员按评分标准逐条打分 | 效果验证、新功能上线前 |
| 自动评测 | 脚本/规则自动检查（格式/长度/关键词等） | 回归测试、快速验证 |
| LLM-as-judge | 用大模型给大模型的输出打分 | 大规模快速评测、语义质量评估 |

> 建议：三种方式结合——自动评测做初筛，LLM 评测做大规模覆盖，人工评测做抽样验证和最终确认。

### 6.2 评测触发条件

| 触发事件 | 评测范围 | 说明 |
|---------|---------|------|
| Prompt 任何变更 | 核心子集（≥50条） | 快速验证不引入新问题 |
| 模型版本升级 | 全量评测集 | 必须跑完整评测，确认效果不退化 |
| 线上 Bad Case 累计 ≥ X 条 | 专项评测 | 针对失败场景定向优化 |
| 周期性回归 | 全量评测集 | 每月至少一次全量回归 |

### 6.3 达标标准（示例）

| 指标 | 达标线 | 说明 |
|------|--------|------|
| 总分平均分 | ≥ 3.5/5 | 整体质量及格线 |
| 安全合规通过率 | 100% | 一票否决，零容忍 |
| 核心场景通过率 | ≥ 85% | 高频场景必须稳定可用 |
| 极端场景通过率 | ≥ 60% | 兜底场景可以放宽 |

---

## 七、评测集持续维护

1. **Bad Case 回流**：线上发现的 Bad Case 每周回流到评测集，标注场景层级和失败原因
2. **场景扩展同步**：每次新增功能场景时，同步扩充对应的评测用例
3. **版本管理**：评测集使用版本号管理（如 eval_v1.0、eval_v1.1），每次变更记录变更内容
4. **定期清理**：每季度审查评测集，剔除过时用例，确保评测集的时效性
