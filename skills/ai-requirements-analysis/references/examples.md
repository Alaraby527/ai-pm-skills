# 示例：AI 智能客服需求分析完整示例

> 本示例基于知识库中的方法论，演示 AI 需求分析的完整输出。为节省篇幅，节选核心部分。

---

## 一、需求背景

### 业务背景
某电商平台客服团队 50 人，日均接待咨询 5000+ 单。随着业务增长，客服人力成本逐年上升，用户等待时间长，满意度下降。希望引入 AI 智能客服降低人工成本、提升响应速度。

### 用户痛点
1. 客服响应慢，高峰期排队 10 分钟以上
2. 简单问题也要等人工，效率低
3. 客服水平参差不齐，回答质量不稳定
4. 夜间/节假日覆盖不足

### 需求目标
- 业务目标：70% 的常见问题由 AI 自动解答，人工成本降低 30%
- 用户目标：平均响应时间从 5 分钟降到 30 秒以内
- 成功衡量：AI 解答准确率 ≥ 85%，用户满意度 ≥ 4.2/5

---

## 二、用户与场景

### 目标用户
- 主要用户：电商平台 C 端消费者（全年龄段）
- 次要用户：客服运营人员（维护知识库、处理复杂问题）

### 典型使用场景

**场景一：订单查询**
- 触发：用户下完单后想知道什么时候发货
- 目标：快速获取订单状态
- 当前痛点：要排队等人工，等了半分钟只问一句话
- 期望：输入问题秒回，直接给答案

**场景二：售后咨询**
- 触发：用户收到商品有问题，想退换
- 目标：了解退换货流程，发起售后申请
- 当前痛点：流程复杂，客服要一步步引导
- 期望：AI 直接告诉怎么做，甚至帮我操作

---

## 三、AI 参与模式与边界

### 模式选择
**混合模式**：
- 简单问题 → Agent 自主模式（AI 全自动解答）
- 复杂问题 → 转人工
- 模糊问题 → Copilot 模式（AI 建议 + 用户选择）

### 分工边界

| 环节 | AI 做什么 | 人做什么 |
|------|-----------|---------|
| 意图识别 | 自动分类用户问题意图 | 处理识别错误的情况 |
| 简单咨询（订单查询/营业时间等） | 自动查询并回答 | 不参与 |
| FAQ 类问题 | 基于知识库自动回答 | 维护知识库内容 |
| 售后/退款等操作 | 引导用户操作，简单情况自动处理 | 复杂/特殊情况人工介入 |
| 投诉/情绪问题 | 安抚情绪后转人工 | 人工跟进处理 |
| 业务范围外问题 | 礼貌兜底回复 | 不参与 |

### 兜底方案
- AI 置信度 < 60% → 直接转人工
- 用户连续 2 次不满意 → 自动转人工
- 用户说"人工"或"转人工" → 立即转接
- 夜间 AI 全部接管，重要问题留到第二天人工回

---

## 四、核心功能方案

### 功能一：智能问答（FAQ + RAG）

**功能描述**：用户提问时，AI 基于知识库自动给出答案。

**技术方案**：
- 高频短问题 → FAQ 知识库（语义相似度匹配）
- 复杂政策类问题 → RAG 文档知识库（向量检索 + 大模型生成）
- 两类知识混合路由，优先 FAQ，FAQ 命中不了再走 RAG

**Prompt 设计要点**：
```
角色：你是 XX 平台的智能客服助手，专业、友好、有耐心。

任务：根据用户的问题和提供的参考资料，给出准确、简洁的回答。

规则：
1. 只回答参考资料中有的内容，不知道就说"抱歉，这个问题我暂时还不会，已为您转接人工客服"
2. 回答要简洁，重点突出
3. 涉及金额、时间等具体数字要准确
4. 态度友好，多用"您"
...
```

| 指标 | 目标值 | 测量方式 |

## 六、MVP 规划

### MVP 功能范围
**必须有**：
1. FAQ 知识库问答（Top 50 问题）
2. 订单查询（对接订单系统）
3. 转人工功能
4. 基础知识库管理后台

**可以没有**：
- RAG 长文档问答
- 多轮复杂对话
- 主动营销
- 多语言

### MVP 验证目标
- 验证：Top 50 问题 AI 解答准确率 ≥ 80%
- 验证：用户接受度（满意度 ≥ 4.0）
- 周期：2 周开发 + 2 周灰度测试

### 迭代路线
- V1.0 (MVP)：FAQ + 订单查询 → 覆盖 30% 问题
- V1.1：RAG 知识库 → 覆盖 50% 问题
- V1.2：售后流程引导 → 覆盖 60% 问题
- V2.0：Agent 自主操作 + 多轮对话 → 覆盖 70%+

# 示例二：电商平台商家AI生成素材产品方案（多节点Agent型）

> 本案例为典型的多节点Agent型AI产品PRD，适合复杂生成类、多步骤流程类场景。

---

## 一、核心问题梳理

**平台侧素材问题4个：**
1. 平台素材同质化，质量参差不齐：同类商品图雷同、白底图泛滥、卖点表达弱，重复素材ctr衰减快。头部5%的SKU贡献40%优质素材，剩余95%存在背景杂乱、分辨率低、卖点不清的问题。
2. 商家素材更新慢：上新快但素材更新滞后，活动图节奏跟不上。大促前商家改图需求激增300%，但受限于产能，只能做主推款换图，大量长尾款无暇顾及。

**根本原因：商家素材生产成本高**
- 中长尾/白牌商家（占比xx%）：无专业拍摄团队，大量使用网图/盗图，极易被折叠或降权。
- 品牌/高运营能力商家（占比xx%）：A/B测试需求极大，需要针对不同人群出不同风格的图，但拍摄成本高。

---

## 二、现状验证（数据支撑）

提取同二级类目、同价格带、同生命周期、相似商品评分的SKU对比，核心结论：
1. AI素材相比非AI素材，并无明显劣势
2. AI素材提升最大的是原本**没有能力做场景图的中长尾/白牌商家**——从"10分白底图"拉到"80分场景图"，CTR提升50%以上
3. 服饰类目的下跌暴露技术瓶颈："面料质感保留"和"模特自然度"是核心制约

---

## 三、产品定位

**面向家居百货、鞋包配饰类目的中低客单价产业带/白牌商家，提供"低门槛、低成本、高可用、高保真、可直接发布"的AI商品素材生产工具。**

- 首发类目：仅开放家居百货、鞋包配饰（数据验证CTR提升最猛、ROI最高、技术最稳定）
- 目标用户：优先中低客单价的产业带/白牌商家

---

## 四、核心目标

### 业务目标
- AI素材大盘CTR提升：首发类目下，AI替换后主图/推荐流图点击率较原图绝对值提升xx%
- AI功能渗透率：上线3个月内，目标品类活跃白牌商家中，AI生图功能使用率达到xx%

### 素材标准（三方视角）
| 视角 | 标准 |
|------|------|
| 平台视角 | 符合类目视觉规范，显著提升大盘CTR/CVR，杜绝侵权和客诉风险 |
| 商家视角 | 可直接商用（高清、无水印、尺寸自适应），清晰表达卖点，无缝分发到多场景 |
| 消费者视角 | 第一眼吸引点击（高审美、光影真实、场景代入感强），点进去不产生落差 |

### 生成时间目标
| 场景 | 目标耗时 | 说明 |
|------|---------|------|
| 单图生成（一键白底转场景） | < x秒 | 含抠图+边缘特征提取+AI重绘+质检全链路 |
| 批量生成（5种场景模板） | < y秒（异步） | 后台并行处理，完成后Toast召回 |
| 修改重生（换同类场景） | < n秒 | Mask和特征已缓存，秒级反馈 |
| 大促高峰期 | 成功率≥99.5% | 并发达平日10倍时 |

### 内容合规（电商场景特有）
**4大维度标准：**
1. **真实性**：材质不得虚假渲染、物理比例误差≤±10%、不虚构产品功效
2. **知识产权**：零第三方品牌乱入、肖像权隔离（禁止高拟真实人面孔）、版权规避
3. **平台底线**：公序良俗红线、广告法合规（禁止极限词）
4. **类目视觉规范**：屏占比60%-80%、背景清爽无牛皮癣

---

## 五、Agent核心流程（11节点）

> 整体分4组：1-4节点负责"理解和上下文构造"，5-7节点负责"生成"，8-10节点负责"筛选与交付"，11节点负责"闭环优化"。

| 节点 | 目标 | 输入 → 输出 |
|------|------|------------|
| 1. 输入解析与商品信息抽取 | 解决商家输入分散、格式不统一的问题 | 商品基础信息+图片信息+商家输入 → task_context标准化JSON |
| 2. 商品图像理解与主体识别 | 正确识别主体、保护商品一致性 | 商品主图+类目+结构化属性 → 透明背景主体图+Caption+Mask遮罩+特征Embedding |
| 3. 意图识别 | 准确推断商家想生成什么图，减少输入成本 | 商品信息+模板选择+卖点输入+历史偏好 → 结构化意图JSON（场景/风格/素材类型/核心卖点） |
| 4. 卖点提炼与文案生成 | 生成视觉图上的文字 | 商品标题+属性+商家输入卖点 → 核心卖点列表+候选短文案+禁止表达清单 |
| 5. 生成任务规划 | 编排底层Agent工作，决定调用哪些子能力 | 商品理解+意图识别+卖点+类目规则 → 模板路由结果+约束参数+候选图数+重试策略 |
| 6. 素材Prompt构造 | 把商品约束/意图/场景/卖点翻译成模型可执行的Prompt | 上游全部结构化结果 → 正向Prompt+负向Prompt+控制参数+版本信息 |
| 7. 图像生成 | 执行素材生成 | 商品图+Prompt+控制参数 → 候选图集（默认6张） |
| 8. 质量打分 | 解决"生成出来不等于可用"的问题 | 候选图+商品原图+卖点要求 → 图像质量分+一致性分+卖点表达分+审美分+综合分 |
| 9. 合规审核 | 确保符合法律法规和平台规则 | 质量通过的候选图+OCR结果+类目 → 审核结论（通过/拦截/转人工）+风险标签 |
| 10. 结果排序与推荐 | 从候选图中选出最优结果交付商家 | 质量分+合规分 → 优选成片库（前1-4张）+多端适配裁切组+主体蒙版数据 |
| 11. 效果数据回流与策略优化 | 数据飞轮闭环 | 商家选图数据+发布采用情况 → Bad Case标注+评测集更新+策略优化 |

### 模型选择逻辑（统一说明）
| 节点 | 模型类型 | 选择逻辑 |
|------|---------|---------|
| 输入解析 | 轻量LLM | 仅需抽取客观字段，高并发下轻模型时延低（<50ms）、成本可控 |
| 图像理解 | 多模态大模型 | 核心考虑识别速度和准确率 |
| 意图识别 | 轻量LLM | 需上下文理解+稳定结构化JSON输出，不选纯分类模型（难覆盖长尾），不选超大模型（成本高） |
| 卖点提炼 | 文本大模型 | 在不虚构卖点前提下压缩为图上短文案 |
| Prompt构造 | 文本大模型 | 动态拼装和自然语言细化，不需多模态主导 |
| 图像生成 | 图生图/编辑模型 | 主图增强用图生图，背景图用背景替换，模特图用人物合成 |
| 质量打分 | 多模态模型 | 审美、一致性、卖点表达不能用简单规则评估 |

## 六、评测体系

### 6大评测维度

| 维度 | 5分标准 | 3分及格线 | 1分（差） |
|------|---------|----------|----------|
| **意图理解准确度** | 准确提取所有实体，精准映射模糊意图，补充字段符合类目常理 | 抓住核心场景，但氛围/视角细节未完全贴合 | 识别错误，场景南辕北辙 |
| **商品一致性** | 轮廓/结构/颜色/材质/Logo 100%还原，光影融合自然 | 轮廓基本正确，但材质质感改变，小Logo模糊 | 关键结构改变，或生成完全不同的物品 |
| **图像生成质量与美感** | 构图高级，光影符合物理规律，无AI痕迹 | 画质清晰，但构图平庸，有轻微塑料感 | 严重伪影、乱码文字、违背物理常识 |
| **卖点表达准确性** | 视觉隐喻完美且有创意，视觉冲击力强 | 卖点表达准确，但手法偏常规 | 完全没有体现卖点，或与卖点背道而驰 |
| **类目适配度** | 完美契合类目属性 | 套用通用模板，未做定制化氛围烘托 | 场景组合不符合生活常识 |
| **合规性** | — | — | 一票否决：涉黄/涉政/血腥/暴力/竞品Logo/侵权 |

### 评测落地方式
| 评测方式 | 目的 | 适用维度 |
|---------|------|---------|
| LLM自动评测 | 看合规、初筛淘汰 | 合规性、基础质量 |
| 标注团队评测 | 多维度打分 | 商品一致性、卖点表达、类目适配度 |
| 产品经理抽检 | 少量盲测验证 | 整体质量把控 |

**初测方案**：研发跑出2000张图Test Set → LLM先审自动打分淘汰 → 剩余分发给标注团队 → 产品经理抽检100张盲测
**达标标准**：单图合格率70%以上可用
