# 逐字稿打磨 Skill

## 简介

**干什么的**：把面试回答从"想到哪说到哪"打磨成"结构清晰、数据扎实、有洞察"的专业表达。基于真实逐字稿逐句诊断，不是写模板答案，而是帮你把自己的经历讲得更好。

**核心方法论**：逐字稿问题诊断（6 类常见问题）+ 回答结构重构（结论先行+数据支撑+逻辑推导+复盘升华）+ 口语化打磨 + 多版本时长控制。

**你能得到什么**：逐字稿问题诊断报告、打磨后的回答逐字稿、表达改进建议、不同时长版本（1 分钟/3 分钟/5 分钟）。

**文件结构**：
```
script-polish/
├── SKILL.md                          # 主文档
└── references/
    ├── polish-checklist.md           # 逐字稿打磨检查清单
```

## 触发场景

- 有面试录音/逐字稿，想知道哪里说得不好
- 项目介绍总是讲不清楚、讲不深
- 回答太长/太短/没有重点
- 表达有口头禅、逻辑跳跃
- 想把书面语改成自然口语
- 模拟面试后需要逐句反馈

> **与 `interview-prep` 的边界**：本 skill 只打磨"已说出口的内容"；项目该讲什么、素材怎么准备、题型框架，去 `interview-prep`。

## 输入要求

**必需信息**：
- 逐字稿或录音转写文本（至少一段完整回答）
- 对应的面试问题

**可选补充信息**：
- 目标岗位 JD
- 期望时长（30 秒/1 分钟/3 分钟/5 分钟）
- 自己觉得不满意的地方

**信息不全时的追问话术**：
- 缺逐字稿："把你回答的原文发给我，越接近真实表达越好（包括'嗯''然后'这些），我才能准确诊断问题。"
- 缺问题："这段回答对应的是什么问题？比如'介绍一个你做过的项目'还是'你为什么从上家离职'？"
- 缺时长要求："这个回答需要控制在多长时间？1 分钟版本和 3 分钟版本的讲法不一样。"

## 工作流（4 步）

### Step 1：逐字稿诊断

对照 6 类常见问题逐句检查：

| 问题类型 | 典型表现 | 严重程度 |
|---------|---------|---------|
| **结构缺失** | 没有结论先行，听半天不知道重点；想到哪说到哪 | P0 |
| **数据缺失** | 全是定性描述（"提升了很多""效果不错"），没有数字 | P0 |
| **逻辑跳跃** | 因果关系不成立，缺少推导过程；"我做了 X，然后就成功了" | P0 |
| **AI 味/套话** | "赋能""抓手""闭环""深度对齐"等堆砌，没有具体内容 | P1 |
| **口头禅/冗余** | "嗯""然后""就是说""对吧"过多；重复说同一件事 | P1 |
| **负面表达** | 抱怨前公司/同事；过度自谦；说"我只是做了…" | P1 |

**检查点**：诊断结论先反馈给用户确认（特别是 P0 类问题是否属实），再开始结构重构。

### Step 2：回答结构重构

按四段式重构回答：

1. **结论先行**（10% 时长）：一句话给出核心答案
2. **数据支撑**（30% 时长）：用具体数字、案例支撑结论
3. **逻辑推导**（40% 时长）：展开思考过程、决策依据、权衡取舍
4. **复盘升华**（20% 时长）：学到了什么、可复用的方法论、如果重来会怎么做

### Step 3：口语化打磨

- 书面语 → 口语："基于上述分析" → "所以我当时判断"
- 长句拆短：一句话不超过 20 个字
- 去除口头禅但保留个人风格：不追求"完美播音腔"
- 增加过渡词："第一…第二…""这里有个关键决策…""结果是…"
- 数字口语化："DAU 从 12 万涨到 18 万，增长 50%" 比 "DAU 提升了 50 个百分点" 更自然

### Step 4：多版本时长控制

| 版本 | 时长 | 适用场景 | 内容要求 |
|------|------|---------|---------|
| 电梯版 | 30 秒-1 分钟 | 自我介绍、快速回答 | 结论 + 1 个核心数据 + 1 个亮点 |
| 标准版 | 3 分钟 | 项目介绍、行为面试 | 结论 + 背景 + 方案 + 数据结果 + 一句话复盘 |
| 深挖版 | 5-8 分钟 | 项目深挖题 | 完整四段式 + 决策细节 + 踩坑经验 + 复盘认知 |

## 质量红线

1. **必须基于用户真实经历打磨**，不允许替用户编造项目经历或数据。
2. **保留用户个人风格**，打磨不是把所有人变成同一个说话方式，而是去除表达障碍。
3. **打磨后的稿子必须读起来像"说话"而不是"背书"**：不允许长难句、书面语堆砌。
4. **每个核心论点必须有数据或具体案例支撑**，不允许"效果很好""提升明显"式空话。
5. **标注修改理由**：不是只给改后版本，要说明"为什么这么改"，让用户理解表达逻辑。
6. **不写负面表达**：抱怨前公司、甩锅同事、过度自谦的内容必须改写。

## 异常兜底

| 异常情况 | 处理方式 |
|---------|---------|
| 用户只有录音没有文字稿 | 建议先转写（可用飞书妙记等工具），或让用户口述回答内容 |
| 逐字稿太短（< 100 字） | 先引导用户展开："能再详细说说当时的情况吗？比如你具体做了什么、遇到了什么困难？" |
| 用户要求写一个"标准答案" | 拒绝直接代写，说明"我帮你打磨你的真实经历，不替你编故事"，提供框架让用户填充 |
| 逐字稿涉及多个问题混在一起 | 先按问题拆分，逐段打磨，最后给出整体反馈 |
| 用户表达基础较好 | 减少基础修改，聚焦在"深度"和"亮点"上——帮用户把"说了"变成"说透了" |

## Skill 联动

- 面试复盘发现表达短板 → 用本 skill 打磨具体回答
- 项目素材来自 `interview-prep` 的 5 维度准备法
- 打磨后的稿子回到 `interview-prep` 做模拟面试验证
