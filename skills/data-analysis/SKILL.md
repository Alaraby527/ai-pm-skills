# 数据分析 Skill

## 简介

**干什么的**：产品数据分析方法论与三大分析模型组合工作流。从指标监控到根因定位，覆盖事件分析、漏斗分析、分层拆解三大核心模型，以及四层指标金字塔、RFM 用户价值分层、数据异常诊断、AB 测试设计、量化模型搭建等方法。

**核心方法论**：四层指标金字塔（业务结果→用户行为→AI质量→系统健康）+ 三大模型组合策略（事件监控发现异常 → 漏斗看转化流失 → 分层拆解定位根因）+ RFM 用户价值分层法 + 数据异常诊断框架 + AB 测试设计方法 + 量化模型搭建。

**你能得到什么**：数据异常根因分析、漏斗分析报告、用户分层结果、指标体系设计（含 AI 专项指标）、数据周报/月报、A/B 测试分析结论、量化模型方案。

## 触发场景

当用户需要分析产品数据、定位数据异常、输出分析报告时触发。典型场景包括：
- 某个指标下跌了，想知道为什么
- 搭建产品数据指标体系（含 AI 产品指标）
- 做漏斗分析、用户分层分析
- 写数据周报/月报/分析报告
- A/B 测试结果分析
- 评估 AI 模型/功能的质量指标

> **与 `survey-questionnaire` 的边界**：问卷回收数据的分析去 `survey-questionnaire`；本 skill 面向业务/行为数据（埋点、漏斗、订单、AI 质量监控）。

## 输入要求

**必需信息**：
- 业务问题或分析目标（要分析什么）
- 数据（数据表格 / 数据描述 / 上传数据文件）

**可选补充信息**：
- 产品类型和业务模式（是否 AI 产品）
- 已知的背景信息（最近做了什么变更）
- 时间范围

**信息不全时的追问话术**：
- 缺数据："目前有哪些数据可以用？是后台导出的表格、数据库查询结果，还是只有大致的数字描述？"
- 缺背景："指标变化前后，产品有没有发版、运营有没有做活动、外部有没有相关事件？"
- 缺目标："这次分析主要想回答什么问题？是找原因、评估效果，还是为决策提供依据？"
- 缺时间范围："想看哪个时间段的数据？有没有可对比的基准期？"

## 工作流（5 步）

### Step 1：明确分析目标与问题定义

- 明确要回答的业务问题（1-3 个核心问题）
- 判断问题类型：
  - **监控型**：指标涨了/跌了多少？
  - **诊断型**：为什么涨/跌？根因是什么？
  - **决策型**：应该怎么做？有什么建议？
- 确定分析的时间范围和颗粒度
- 确认数据是否可得、口径是否一致

**检查点**：进入分析前，向用户复述问题类型（监控/诊断/决策）、时间范围与指标口径，确认数据可得。

### Step 2：搭建指标体系——四层指标金字塔

| 层级 | 指标类型 | 说明 | 典型指标 |
|------|---------|------|---------|
| **L1 业务结果层** | 北极星指标 + 一级业务指标 | 衡量产品最终商业价值 | DAU/MAU、收入、付费率、LTV、留存率 |
| **L2 用户行为层** | 过程指标 | 衡量用户在产品中的行为 | 功能使用率、访问深度、人均时长、转化率 |
| **L3 AI 质量层**（AI 产品必选） | AI 能力效果指标 | 衡量 AI 输出的质量和可靠性 | 准确率、召回率、幻觉率、忠实度、拒答率、采纳率、人工干预率 |
| **L4 系统健康层** | 技术性能指标 | 衡量系统稳定性和性能 | 响应时长（P50/P95/P99）、错误率、可用性、Token 消耗 |

**L3 AI 质量指标详解**（AI 产品分析时必须覆盖）：

| 指标 | 定义 | 测量方式 |
|------|------|---------|
| 准确率（Accuracy） | AI 输出正确的比例 | 人工标注/自动评测集 |
| 召回率（Recall） | 应返回的结果中实际返回的比例 | 评测集对比 |
| 幻觉率（Hallucination Rate） | AI 编造不存在信息的比例 | 人工抽检/事实一致性检测 |
| 忠实度（Faithfulness） | 回答是否基于给定上下文，不编造 | RAG 场景：回答与检索内容的一致性 |
| 拒答率（Refusal Rate） | AI 拒绝回答的比例 | 日志统计（区分合理拒答 vs 过度拒答） |
| 采纳率（Adoption Rate） | 用户采纳 AI 建议/输出的比例 | 用户行为埋点（点击"采用"/"复制"） |
| 人工干预率 | AI 输出后被人工修改的比例 | 修改行为埋点 |
| Bad Case 率 | 用户标记"不好"的比例 | 反馈按钮统计 |

### Step 3：事件分析——看大盘，发现异常

> **执行顺序说明**：本节默认顺序为"事件分析→漏斗→分层"。实际执行时，**按下方《三大模型组合使用策略》根据问题类型选择先后**（如"转化率下降"应先做漏斗分析找流失环节，再看分层定位人群，最后事件分析复核拐点）。

**事件分析基础**：
- 核心指标是什么（北极星指标 + 一级指标）
- 指标怎么算（定义、口径、分子分母）
- 看趋势：日/周/月趋势、同比、环比

**异常识别**：
- 指标是否在正常波动范围内？
- 和前一周期相比变化了多少？
- 是突增突降还是持续趋势？
- 从什么时候开始变化的？（拐点定位）

### Step 4：漏斗分析 + 分层拆解——定位根因

> 事件分析发现异常 → 漏斗分析找到流失环节 → 分层拆解定位是哪群人/哪个渠道的问题

**漏斗分析**：
1. 确定核心用户路径
2. 拆分关键节点
3. 计算各层转化率
4. 找到流失最大的环节
5. 进一步分析流失原因

**分层拆解**：

| 分层维度 | 说明 | 适用场景 |
|---------|------|---------|
| 渠道分层 | 按获客渠道拆分 | 新增/留存变化时 |
| 地域分层 | 按城市级别/地区拆分 | 本地化相关产品 |
| 行为分层 | 按是否使用核心功能、是否付费拆分 | 功能渗透率、付费分析 |
| RFM 分层 | 按消费行为三维度打标签 | 电商/付费产品用户价值 |
| 版本分层 | 按产品版本拆分 | 版本迭代效果评估 |
| 新鲜度分层 | 按注册时长拆分 | 新老用户差异 |
| **AI 能力分层**（AI 产品） | 按 AI 输出质量分层（高/中/低置信度） | AI 功能效果分析 |

**贡献度计算（标准化分解法）**：分层表中的"贡献度"不能拿两个百分比直接相减——维度结构占比与分层内转化率往往同时变化（辛普森式混杂）。标准做法：
1. 固定基期的维度结构，套用当期的分层内转化率 → 与基期整体值的差 = **转化率效应**（分层内质量变化的影响）
2. 当期整体值 − 上一步结果 = **结构效应**（维度占比变化的影响）

示例：整体激活率 42.9%→34.0%（-8.9pp）；固定基期渠道结构（80%/20%）、套用当期渠道内转化率（40%/25%）得 37.0%，则渠道内转化率效应 = 42.9−37.0 = 5.9pp，渠道结构效应 = 37.0−34.0 = 3.0pp。

**RFM 用户价值分层四步流程**：
1. 提取历史订单数据，整理 R/F/M 原始数据
2. 按分位数给三维度打分（1-5 分）
3. 计算三维度均值，区分「高/低」两档
4. 2×2×2 组合出 8 类价值用户

### Step 5：输出分析报告

按 `references/template-analysis-report.md` 模板输出，包含：
- 分析背景与目标
- 核心结论（先给结论，再展开）
- 详细分析（事件 + 漏斗 + 分层）
- 原因分析与验证
- 行动建议
- 后续跟进指标

## A/B 测试设计方法

当需要评估功能/策略效果时使用：

| 步骤 | 内容 | 注意事项 |
|------|------|---------|
| 1. 确定实验假设 | "做 X 会导致 Y 指标提升 Z%" | 假设必须可证伪 |
| 2. 确定核心指标 | 1 个主指标 + 2-3 个护栏指标 | 护栏指标防止"拆东墙补西墙" |
| 3. 计算样本量 | 根据基线转化率、最小可检测效应（MDE）、显著性水平（通常 5%）、统计功效（通常 80%）计算 | 样本量不足会导致假阴性 |
| 4. 确定分流方式 | 用户级分流，保证同一用户始终在同一组 | 注意分流均匀性检验 |
| 5. 确定实验周期 | 至少覆盖一个完整业务周期（通常 1-2 周） | 避免周末效应、节假日干扰 |
| 6. 分析结果 | 显著性检验（p < 0.05）+ 置信区间 + 效应量 | 不要只看 p 值，还要看实际业务价值 |

## 量化模型搭建方法

当需要从数据中提炼可复用的判断标准时：

1. **定义目标变量**：要预测/分类什么（如"用户是否付费"）
2. **选择特征**：哪些行为数据可能相关（使用频率、功能偏好、注册时长等）
3. **数据准备**：清洗、缺失值处理、特征编码
4. **模型选择**：根据业务场景选择（规则引擎 / 逻辑回归 / 决策树 / 聚类）
5. **验证与迭代**：用历史数据回测，关注精确率和召回率的平衡
6. **上线监控**：模型上线后持续监控衰减，定期重训练

## 三大模型组合使用策略

| 问题 | 先用什么模型 | 再用什么模型 | 最后用什么模型 |
|------|-------------|-------------|---------------|
| DAU 跌了，为什么？ | 事件分析（看趋势、看拐点） | 分层拆解（按渠道/版本/新老用户） | 漏斗分析（看是哪个环节掉了） |
| 转化率下降 | 漏斗分析（找到流失最大的环节） | 分层拆解（看哪类用户掉得多） | 事件分析（看该环节的具体指标） |
| AI 回答准确率下降 | 事件分析（看准确率趋势） | 分层拆解（按问题类型/模型版本） | Bad Case 分析（看具体错在哪） |
| 留存率下跌 | 事件分析（看各日留存曲线） | 分层拆解（按渠道/版本/行为） | 漏斗分析（新手流程哪步流失） |

## 数据分析五个常见误区

| # | 误区 | 正确做法 |
|---|------|---------|
| 1 | **相关当因果**：两个指标一起变化就认为有因果关系 | 控制变量、AB 实验验证、排除混淆变量 |
| 2 | **辛普森悖论**：整体看 A 组好，但拆分后每组都是 B 组好 | 分层后再看结论，注意分组权重差异 |
| 3 | **幸存者偏差**：只分析留下来的用户，忽略流失用户 | 纳入流失用户数据，分析流失原因 |
| 4 | **平均数陷阱**：只看均值，忽略分布 | 看中位数、分位数、分布形态，警惕被极端值带偏 |
| 5 | **数据口径不一致**：不同报表的同一指标数字不同 | 分析前先对齐指标定义、统计口径、时间范围 |

## 质量红线

1. **结论先行**：报告开头必须给出核心结论（1-3 条），不能让读者自己从数据里找答案。
2. **每个结论必须有数据支撑**：不允许"我觉得""可能是"式的无依据判断；推测必须标注"假设"并给出验证方法。
3. **AI 产品分析必须覆盖 L3 AI 质量指标**，只分析 DAU/留存等业务指标不合格。
4. **指标口径必须明确**：每个指标要写清定义、计算公式、统计时间范围，避免口径不一致。
5. **不编造数据**：没有数据时明确说"暂无数据"，不凭空推测具体数值。
6. **AB 测试结果必须报告显著性和效应量**，不能只看数字差异就下结论。

## 异常兜底

| 异常情况 | 处理方式 |
|---------|---------|
| 数据缺失/不完整 | 明确说明数据缺口和对结论的影响，用可用数据做有限分析，标注结论置信度 |
| 指标口径不清 | 先对齐口径再分析，不带着歧义做分析 |
| 数据量太小（< 30 样本） | 不做统计显著性检验，只做描述性分析，明确标注"样本量不足，结论仅供参考" |
| 找不到明确根因 | 列出 2-3 个最可能的假设，给出验证方案，不强行编一个原因 |
| 多个因素同时变化 | 用控制变量法逐个排除，无法排除时说明"多因素叠加，无法单独归因" |
| 用户只有描述没有数据文件 | 基于描述给出分析框架和需要收集的数据清单，不凭空分析 |
