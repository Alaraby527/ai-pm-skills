# 产品体验报告 Skill

## 简介

**干什么的**：基于用户体验五要素的产品体验分析方法论工具包。从战略层到表现层五层拆解，系统性分析一款产品的设计思路和体验优劣。

**核心方法论**：用户体验五要素模型（战略层→范围层→结构层→框架层→表现层）+ 五要素逐层分析 checklist + 综合总结框架。

**你能得到什么**：完整产品体验报告、产品结构分析、核心设计优缺点总结、可借鉴的设计方法、对己方产品的启示。

**文件结构**：
```

├── SKILL.md                              # 主文档：触发条件 + 工作流 + 质量红线

```

## 触发场景

当用户需要系统性分析一款产品的用户体验时触发。典型场景包括：
- 深度拆解一款产品的设计思路
- 写产品体验报告 / 产品分析文章
- 面试前的产品分析准备
- 竞品体验对比
- 从一款产品中学习产品设计方法

## 输入要求

**必需信息**：
- 产品名称（至少 1 款）

**可选补充信息**：
- 分析侧重点（功能/设计/商业化/AI 能力等）
- 分析深度（快速扫描 / 深度体验）
- 输出形式（报告/PPT/面试答题）

**信息不全时的追问话术**：
- 只给了产品名："你分析这款产品主要想解决什么问题？是学习设计方法、做竞品参考，还是准备面试？我会调整侧重点。"
- 产品无法直接体验："这款产品需要邀请码/付费才能使用，我可以基于公开信息（官网、评测、用户评论）做桌面分析，但会标注分析局限。可以吗？"

## 工作流（5 步，对应五要素）

### Step 1：战略层分析——为什么做

分析产品最底层的定位和目标：

1. **市场定位**：这款产品解决什么人的什么问题？处于什么赛道？
2. **目标用户**：核心用户是谁？有什么特征？
3. **商业目标**：产品靠什么赚钱？公司为什么做它？
4. **用户需求**：用户为什么用它？满足了什么需求？

**输出**：战略层分析结论 + 产品定位一句话总结

### Step 2：范围层分析——做什么功能

1. **功能全景图**：按模块列出所有核心功能
2. **核心功能 vs 次要功能**：哪些是必须有的，哪些是锦上添花的
3. **AI 能力边界**（AI 产品适用）：AI 做了什么？没做什么？
4. **功能与战略的匹配度**：每个功能是否支撑战略目标？
5. **功能取舍**：产品故意不做什么？为什么？

**输出**：功能清单 + 功能模块分类 + 核心功能标注

### Step 3：结构层分析——功能怎么组织

1. **功能模块划分**：产品有几个大模块？每个模块负责什么？
2. **信息架构**：内容如何组织和分类
3. **用户流程图**：核心任务的完整流程
4. **AI 参与模式**（AI 产品适用）：Copilot / Agent / 插件模式

**输出**：模块结构图 + 核心用户流程图

### Step 4：框架层分析——页面怎么排版

1. **页面布局逻辑**：信息是怎么排布的？为什么这么排？
2. **导航设计**：用户如何在页面间跳转？
3. **交互设计**：关键操作的交互方式
4. **首屏设计分析**：首页各区域的设计目的和优缺点

**输出**：核心页面框架分析 + 交互优缺点

### Step 5：表现层分析——长什么样

1. **视觉风格**：整体风格定位
2. **配色方案**：主色/辅助色/功能色
3. **品牌元素**：Logo、插画、动效
4. **视觉细节**：圆角、阴影、间距、字体

**输出**：视觉设计总结 + 优缺点

### 最后：综合总结

- 产品整体体验评价（1-10 分 + 评分理由）
- 最值得学习的 3 个设计点
- 可以改进的 3 个地方
- **对我们/对你的启示**（不少于 2 条可执行建议）

## 五要素记忆口诀

> **战略层** = 为什么做（市场、用户、目标）
> **范围层** = 做什么功能（落地战略）
> **结构层** = 功能怎么拆分、页面分什么模块
> **框架层** = 页面怎么排版、交互怎么做
> **表现层** = 视觉、色彩、动效设计

## 质量红线

1. **五层必须逐层分析，不得跳过任何一层**。五层是递进关系，跳过任何一层都会导致分析断裂。
2. **必须有实际体验支撑**：每个判断必须基于具体页面/功能/交互细节，不允许空泛评价（如"体验很好""设计不错"而不说具体哪里好）。
3. **结论必须落到启示**：纯分析无启示不合格，至少给出 2 条可执行的借鉴/改进建议。
4. **客观评价，避免主观偏好**：优缺点都要写，不能只夸不贬或只贬不夸。评价标准是"是否匹配目标用户和战略"，不是个人喜好。
5. **AI 产品必须分析 AI 能力边界和参与模式**，不能只分析传统 UI 层面。

## 异常兜底

| 异常情况 | 处理方式 |
|---------|---------|
| 产品无法访问/需邀请码 | 降级为桌面分析（官网+应用商店截图+第三方评测+用户评论），在报告开头说明分析局限 |
| 产品已下架/停止运营 | 基于历史资料（存档、评测文章、用户回忆）分析，标注"产品已下线，分析基于历史信息" |
| 用户要求分析自己不熟悉的小众产品 | 先搜索产品基本信息（官网、报道、用户评价），再开始分析，不凭名字猜测 |
| 分析深度要求过高但时间有限 | 先出快速扫描版（五层各 2-3 个核心判断），标注可深入的方向，让用户选择是否继续 |
| 产品包含大量功能无法全部体验 | 聚焦核心功能路径（新用户首次使用 + 1-2 个核心任务），次要功能列入功能清单但不深拆 |
