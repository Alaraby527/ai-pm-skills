# 简历-JD 对齐 Skill

## 简介

**干什么的**：用产品经理的思维优化简历——把目标 JD 当作"需求文档"，把简历当作"产品方案"，精准匹配、量化成果。同时覆盖求职规划与投递策略。

**核心方法论**：JD 三类关键词提取法 + 简历三大黄金标准 + 五大致命错误自查 + 四模块架构 + 万能项目描述公式（背景+方案+亮点+结果+复盘）+ 三梯队岗位盘点 + 三阶段投递策略。

**你能得到什么**：JD 关键词匹配分析、简历结构体检报告、优化后的简历内容、项目描述改写、自我评价精炼、三梯队岗位表、投递节奏规划。

**文件结构**：
```
resume-jd-align/
├── SKILL.md                          # 主文档
└── references/
    ├── resume-template.md            # 简历优化模板与范例
    ├── job-search-strategy.md        # 求职规划与投递策略
    └── prompts.md                    # 提示词合集
```

## 触发场景

- 投了很多简历没回应，想知道问题出在哪
- 拿到一个 JD，想针对性优化简历
- 项目经历写得像职责描述，不知道怎么改
- 转行/转岗不知道怎么突出优势
- 想做求职规划、岗位盘点、投递策略

> **与 `interview-retro` 的边界**：简历投出去没回应、简历本身要改，在本 skill；已有面试记录、要算各轮转化率漏斗，去 `interview-retro`。

## 输入要求

**必需信息**：
- 目标 JD（岗位描述），或至少说明目标岗位方向
- 当前简历内容（或主要经历描述）

**可选补充信息**：
- 求职诉求（跳槽原因、薪资预期、目标公司）
- 工作年限、当前职级
- 是否有目标行业/赛道偏好

**信息不全时的追问话术**：
- 缺 JD："有目标岗位的 JD 吗？发给我可以做精准匹配。如果还没有，我可以先帮你做简历结构体检和通用优化。"
- 缺简历："方便发一下你现在的简历吗？或者口述一下主要工作经历和项目经历也可以。"
- 缺求职诉求："你这次跳槽最核心的诉求是什么？比如薪资、成长空间、行业方向、团队规模？我会据此帮你排岗位优先级。"

## 工作流（5 步）

### Step 1：跳槽诉求澄清（如需求职规划）

用「五大矛盾」定位核心诉求：
1. 薪资矛盾（内部调薪远低于跳槽溢价）
2. 行业发展矛盾（赛道下行/兴趣背离）
3. 成长权限矛盾（无独立操盘/带人机会）
4. 团队氛围矛盾（管理风格/加班文化）
5. 价值实现矛盾（重复无产出）

**三问判断是否该跳**：
- 是否为现阶段第一主要矛盾？
- 是否触碰个人底线？
- 内部是否存在解决方案（调岗/新项目）？

### Step 2：目标 JD 拆解

从 JD 中提取 3 类关键词：
- **硬技能关键词**：AI 产品、RAG、Prompt 工程、数据分析等
- **业务场景关键词**：智能客服、知识库、推荐系统等
- **软素质关键词**：跨部门推动、从 0 到 1、数据驱动等

→ 这些关键词就是简历的"命中靶心"。输出 JD 关键词清单 + 权重排序。

**检查点**：把关键词清单和权重排序交用户确认后，再开始简历体检（关键词漏提会导致后续全部返工）。

### Step 3：简历结构体检

**三大黄金标准**：
1. 结构清晰、可读性强（HR 3 秒定位关键词）
2. 高度匹配 JD（岗位选择+项目描述双维度贴合）
3. 描述精准有逻辑（用数据、业务结果体现价值）

**五大致命错误自查**：
1. 基础排版问题（错别字、多字体、4-5 页长篇）
2. 结构混乱（个人/工作/项目混杂）
3. 无效自我评价（空泛"逻辑强、沟通好"无佐证）
4. 项目泛化（"做调研、写方案、跟进上线"谁都能写）
5. 无数据支撑（只讲做了什么，不讲带来什么价值）

### Step 4：简历内容重构

**四模块架构**：

| 模块 | 内容要点 | 注意事项 |
|------|---------|---------|
| 个人信息 | 姓名、电话、邮箱（3 项必备） | 照片可选，需正式精神 |
| 教育经历 | 时间、学校、专业、学历（倒序） | 学校弱可后置到末尾 |
| 工作经历 | 任职信息+公司简介+核心工作+量化成果 | 业务线 PM 聚焦用户/营收指标 |
| 项目经历 | 2-4 个高匹配项目，用万能公式写 | 重中之重，占简历 50% 以上权重 |

**万能项目描述公式**：
```
项目标题 + 背景 + 方案 + 核心亮点 + 数据结果 + 复盘认知
```
- **背景**：业务痛点、用户未被满足需求、商业价值
- **方案**：完整设计逻辑，每条功能/策略对应明确需求
- **亮点**：解决行业通用难点、创新策略、跨部门推动案例
- **结果**：和预设目标对比，**必须量化**
- **复盘**：成功/失败带来的产品认知升级

**无量化数据时的处理**：替换为产品长期价值（搭建 XX 组件、提升业务复用效率），但不得编造数字。

**自我评价精炼（2-3 行，拒绝空话）**：
1. 经历概括：明确从业年限、深耕赛道、核心操盘模块
2. 差异化亮点：大厂背书/从 0 到 1/核心增长成果，**所有描述必须在项目中有对应论据**

### Step 5：投递策略（如需）

**三梯队岗位盘点（至少 40 个）**：

| 梯队 | 定义 | 数量建议 | 作用 |
|------|------|---------|------|
| 第一梯队（冲刺岗） | 5 维度高匹配 | 5-8 个 | 最终冲刺目标 |
| 第二梯队（主力岗） | 核心 2-3 项匹配 | 15-20 个 | 拿保底 offer，维持手感 |
| 第三梯队（试水岗） | 匹配度一般 | 10-15 个 | 暴露短板，练手 |

**三阶段投递策略（3 个月周期）**：试水期（2-3 周投第三梯队）→ 大规模投递期（4 周主投第二梯队）→ 冲刺期（3-4 周投第一梯队）。

## 质量红线

1. **项目描述必须使用万能公式六要素**，缺"数据结果"或"复盘认知"不合格。
2. **不编造数据**：没有量化数据时用定性描述（"搭建了 XX 体系""提升了复用效率"），绝不虚构数字。
3. **自我评价的每一句话必须在项目经历中有对应论据**，不允许空泛的"逻辑强、沟通好"。
4. **简历必须与 JD 关键词对齐**：优化后要标注哪些 JD 关键词已命中、哪些未覆盖。命中率口径：按 Step 2 关键词清单逐项判定命中，P0 关键词每项记 2 分、P1/P2 记 1 分，命中率 = 已得分 ÷ 满分，≥ 70% 达标（与 `resume-template.md` 自查清单一致）。
5. **简历长度控制在 2 页以内**（5 年以下经验 1 页），不允许 4-5 页长篇。
6. **不使用 AI 味过重的套话**（"赋能""抓手""闭环"等堆砌），用具体事实说话。

## 异常兜底

| 异常情况 | 处理方式 |
|---------|---------|
| 用户没有具体 JD | 先做通用简历体检 + 按目标岗位方向给出关键词建议，拿到 JD 后再做精准对齐 |
| 用户经历与目标 JD 差距大 | 诚实指出差距，给出"可迁移能力"的包装策略，不建议硬凑不相关经历 |
| 用户没有量化数据 | 教用户如何找数据（后台查询、对比估算、定性价值），实在没有就用定性描述 |
| 转行/转岗用户 | 重点挖掘可迁移能力，用"通用能力+业务理解"框架重写，不假装相关经验 |
| 用户简历有多个方向 | 建议针对不同方向准备多个简历版本，不做"一份简历投所有岗位" |
