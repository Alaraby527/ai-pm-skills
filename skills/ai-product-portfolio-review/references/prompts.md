# 审查提示词库

## 证据提取

```text
请只从作品集原文和用户提供的补充材料中提取可验证证据，不要补写事实。按以下字段输出：目标用户、具体问题、问题证据、传统方案、AI必要性、业务复杂度、项目类型、项目成熟度、核心含金量模块、人机分工、工作流、工程化边界、上下文策略、失败/badcase、评测数据、迭代与回流、用户/业务结果、限制。每项标注原文位置，并区分“作品集直接证据 / 用户补充证据 / 合理推断 / 待补证据”。
```

## 项目成熟度与三大标准

```text
请按“业务复杂度、真实生产与迭代闭环、与业务匹配的当前技术方案”审查这个 AI 项目。先判断它是概念、可运行 Demo、试点/内测还是生产使用，并列出支持该判断的证据；没有用户、流量、日志、反馈或上线边界时，不得写成生产项目。再输出：最复杂的业务场景、核心高含金量模块、badcase→定位→修改→复测→回流链路、技术方案取舍，以及最小修复动作。
```

## 项目硬伤审查

```text
请以面试官追问视角审查这个 AI 产品项目。重点判断：它是否只是模型套壳或一问一答；是否解释为什么不用规则/搜索/表单；业务复杂度是否真实；是否展示了错误、回退、人工确认、工程边界、评测、badcase回流和迭代；项目成熟度是否被夸大；技术名词是否只是模板化堆砌。不要因为技术名词多就加分。输出硬伤、证据位置和最小修复动作。
```

## 多项目主项目选择

```text
请在不按项目数量加分的前提下，为这份作品集选择主项目。比较每个项目的问题真实性、业务复杂度、核心含金量模块、成熟度/真实度、评测与迭代证据、用户/业务价值、差异化和可追问性。输出推荐排序、每个项目的保留/重做/移除建议，以及主项目选择理由；证据不足处标记“待补”，不要凭技术栈推断。
```

## 版式审查

```text
请逐页审查这份作品集的扫描效率和可读性。检查每页主结论、标题是否结论式、六段结构、信息层级、页面密度、字体大小、对齐、留白、颜色对比、流程图/截图是否服务于决策、badcase/评测/版本对比是否可定位，以及导出后的裁切、模糊和重叠。把“影响面试判断的问题”和“纯审美偏好”分开；没有渲染或逐页截图时，版式总体结论写“无法完整核验”。
```

## 事实安全改写

```text
请在不新增事实的前提下改写以下项目描述。保留所有真实数字、成熟度、限制和不确定性；对缺少证据的地方使用“待补：...”标记，不要生成访谈、用户反馈、上线数据、生产流量或模型准确率。优先改成“问题—业务复杂度—判断—行动—证据—结果/限制”的结构，并把 Demo、试点和生产使用分开表述。
```

## 面试追问

```text
针对这个项目生成 10 个高概率面试追问，覆盖：问题真实性、传统方案对比、业务复杂度、AI选择、项目成熟度、模型边界、工作流、工程化、异常回退、上下文、评测集、badcase、成本/延迟取舍、迭代与业务结果。每个问题后说明作品集中当前缺哪一条证据。
```

## 项目构建计划

```text
如果用户是在“还没有完整项目”的情况下寻求行动计划，请给出可调整的 7 天最小闭环计划：选题与3名目标用户、传统方案对比、跑通主流程、约20–50条测试集、一次badcase迭代、整理约5–8页报告和约90秒演示。明确这些是建议产出，不是已经完成的事实，也不是审查硬门槛。
```

## 信息不足时的最小追问模板

```text
为了准确审查，请补充能提供的材料：
1. 目标岗位/JD（没有则按通用 AI PM 岗位）；
2. 作品集正文 + PDF/PPTX/DOCX/逐页截图（没有视觉材料则只能审查文本）；
3. 可编辑源文件（希望直接修改时必需；只有 PDF 则输出逐页修改方案）；
4. 测试集、基线、badcase 与改前后对比（没有则标记评测证据缺失）；
5. 用户/试点/生产证据与指标口径（没有则不得写成上线或生产）。
请只提供可公开或已脱敏的材料；未提供项我会逐项标记为“待补/未核验”。
```

## 异常兜底提示词

```text
如果文件打不开、格式不支持、渲染失败、链接无法访问或材料只有不可编辑 PDF：
- 先说明具体失败环节；
- 继续审查仍可读取的文本和结构；
- 把外部材料、视觉质量、生产状态和结果证据标记为“未核验”；
- 给出最小替代材料（逐页截图、可编辑源文件、脱敏日志/指标口径）；
- 不把“无法访问”写成“没有实现”，也不补造数字、用户、上线状态或评测结果。
```
