# AI PM 作品集评审标准

## 核心问题

审核时必须能回答：

1. 具体用户和问题是什么，问题证据在哪里？
2. 为什么用 AI，而不是搜索、规则、数据库、表单或人工？
3. 用户输入后经过哪些数据、模型、工具、校验和人工步骤？
4. 模型会在哪里出错，如何发现、回退、转人工或重试？
5. 效果、延迟、成本、隐私和业务风险如何取舍？
6. 版本迭代改了什么，指标或用户结果如何变化？
7. 用户或业务是否真的愿意使用，证据是什么？

## 六大证据维度

| 维度 | 应检查的证据 | 常见缺口 |
|---|---|---|
| 真实业务与问题选择 | 目标用户、具体行为、发生环节、频率/代价、访谈/观察/工单/业务数据 | 宏大痛点、伪需求、无用户证据 |
| 技术选型与 AI 专项设计 | AI 必要性、模型取舍、Prompt 迭代、RAG/知识库、上下文、工具调用、成本账 | 技术名词堆砌、未解释为何不用简单方案 |
| 工作流与人机协同 | 输入、数据/工具、AI 节点、校验、人工确认、低置信度、异常回退、数据回流 | 只有“用户提问 → 模型回答” |
| 工程体系与可落地性 | 数据结构、API、权限、日志、会话、多用户、并发、异常、可观测、任务规划与结果核验 | 只调 Prompt，声称企业级但没有边界 |
| 评测与量化复盘 | 测试集/金标准、基线、准确性/完成率、延迟、成本、采纳、合规、AB 或对照 | 全凭演示，没有口径和基线 |
| 失败案例与迭代闭环 | badcase、错误分类、定位、Prompt/知识库/交互/工作流修改、复测、回流、未解决问题 | 只有成功案例，只写“项目完成” |

没有证据时写 `待补/未证明`，不要用推断替代证据。

## 六段项目结构

每个项目应覆盖以下信息，顺序可按叙事调整：

1. **业务背景**：具体、真实、尽可能可量化的痛点。
2. **用户场景**：一个目标用户和一个高频核心场景，避免大而全。
3. **人机方案**：AI 与人的分工、人工确认点、低置信度处理和风险边界。
4. **AI 专项设计**：模型、Prompt、RAG/知识库、上下文、工具调用、Memory、Skill/MCP 的取舍依据。
5. **流程闭环**：输入 → 智能处理 → 校验 → 输出 → 异常/重试/回退/审核/结果核验。
6. **量化复盘**：结果、准确性、耗时、成本、用户/业务变化、版本对比和限制。

## AI 功能 PRD 的五个专属章节

- AI 能力选型：模型、第三方 API/自研、选择理由和成本约束；
- Prompt 与交互设计：角色、上下文、输出约束、反馈和版本变化；
- 效果评估指标：成功定义、测试集、基线、指标口径和对照方式；
- Badcase 处理机制：错误类型、发现、兜底、转人工和修复；
- 数据闭环：反馈如何记录、筛选、回流测试集并驱动迭代。

## 项目成熟度证据

| 成熟度 | 可用表述 | 不足时的限制 |
|---|---|---|
| 概念/方案 | 设计、规划、拟验证 | 不能暗示已实现或有结果 |
| 可运行 Demo | 跑通主流程、样例验证 | 不能暗示真实用户或生产效果 |
| 试点/内测 | 小范围试用、灰度验证 | 需要对象、范围、反馈或记录 |
| 生产使用 | 上线、生产使用、业务结果 | 需要用户/流量/日志/反馈/指标/上线边界等可核验证据 |

“无法访问”不等于“没有实现”；只能写为 `外部材料未核验`。

## 项目类型检查

| 类型 | 重点能力 | 主要风险 |
|---|---|---|
| 工作流 Agent | 工具调用、任务规划、流程边界、异常回退 | API 串联但没有真实价值 |
| AI 评测/质量工具 | 测试集、评价标准、错误分析、模型选择 | 只测模型，不连接产品目标 |
| AI + 垂直行业 | 行业流程、业务约束、差异化 | 通用聊天机器人换皮 |

多项目选择主项目时，优先问题真实性、业务复杂度、核心模块、成熟度、评测与迭代、用户/业务价值和可追问性，不按技术栈数量或项目数量加分。

审核还应记录候选人的个人职责、具体贡献和决策边界；团队成果不能自动归因给个人，未提供时标记 `个人贡献待补`。

## 视觉与信息表达

有渲染页或逐页截图时检查：封面定位与项目排序、项目首页结论、每页主结论、输入输出流程、人机边界、错误分类、指标对比、版本对比、字号、密度、对齐、留白、对比度、图片清晰度、字体兼容性、断页、裁切、重叠和链接。

没有视觉材料时，只审查文本结构和版式意图，必须写 `无法完整核验（缺少视觉材料）`；不要把主观审美偏好写成硬伤。

## 红线

- 编造访谈、用户、上线、指标、收入、留存、流量、反馈或业务成果；
- 把 Demo、架构图、RAG、Agent 或成功样例写成生产事实；
- 只有模型输入输出，没有业务工作流、失败防御或人工回环；
- 把规则明确的任务强行包装成 AI 需求而不说明取舍；
- 涉及资金、隐私、对外发布、关键审批却没有人工确认和权限边界；
- 关键页面不可读，导致证据无法核验。

## 建议报告字段

```text
结论摘要：
审核范围与未核验项：
视觉材料状态：
目标岗位/使用场景：
项目名称 / 类型 / 成熟度 / 作品集角色：
个人职责/贡献与边界：
内容判定：达标 / 基本达标 / 不达标 / 无法完整核验
版式判定：达标 / 基本达标 / 不达标 / 无法完整核验
已有证据：
待补证据：
P0/P1/P2 问题：
最小修改动作：
面试追问：
修改记录：
修改后验收条件：
```

严重程度：P0 是事实安全、权限隐私或不可交付问题；P1 是影响可信度、成熟度和面试判断的问题；P2 是局部表达和视觉优化。
