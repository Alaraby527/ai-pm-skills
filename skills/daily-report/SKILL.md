# 日报助手

## 目标

将用户提供的工作记录、聊天摘录、任务清单或口述内容，整理成真实、清晰、可直接发送的中文工作日报。以工作结果和实际价值为主线，不按时间顺序机械罗列，不写成流水账。

## 适用场景

以下需求适用本 Skill：

- 帮我写今天的日报
- 整理今日工作进展
- 把这些工作记录整理成日报
- 生成一份工作汇报
- 总结今天完成的事项、效果、问题和明日计划
- 将学习内容和工作进展合并成日报

不适用于周报、月报、项目复盘或正式绩效总结；用户明确要求这些类型时，按用户要求处理，不强行套用本模板。

## 输入信息

### 必需信息

至少提供以下任意一类信息：

- 今日完成事项或工作结果
- 工作中发现的问题及处理方式
- 当前卡点、支持需求或明日计划

### 可选信息

- 日期
- 项目或任务名称
- 数量、比例、耗时、质量、效率等数据
- 问题原因、解决过程和当前状态
- 需要支持的对象或具体资源
- 学习文档名称、学习内容和收获
- 输出风格，例如简短版、正式版、群聊版或领导汇报版

### 默认处理

- 未提供日期：使用当前本地日期，并计算对应星期。
- 未提供数据：不补造数字，使用克制的定性表达或标记“待补充数据”。
- 未提供某个栏目：保留栏目并写“暂无”或“待补充”。

## 工作流程

1. **提取事实**
   - 提取日期、完成事项、工作结果、效果、问题、处理方式、卡点、支持需求和明日计划。
   - 产出：事实清单，不添加用户未提供的结论。

2. **按结果归类**
   - 将信息归入今日完成、效果与提升、问题及处理方式、卡点与支持、明日计划。
   - 合并同类事项，删除重复描述和无关过程。
   - 产出：按主题整理的信息。

3. **融合学习内容**
   - 将阅读、培训、文档学习等内容放入“今日完成”。
   - 直接描述掌握的重点、形成的认识或对工作的启发，不使用“我的理解是……”等固定句式。
   - 产出：包含学习收获的完成事项。

4. **组织日报**
   - 使用标准输出结构。
   - 优先采用“动作+产出/效果”的表达，例如“完成接口联调，输出测试结果”。
   - 尽量少用“了”等完成时语气词，保持简洁、客观。
   - 产出：日报初稿。

5. **输出检查**
   - 检查日期、事实准确性、问题与处理方式的对应关系、栏目完整性和表达风格。
   - 产出：可直接发送的日报。

## 日期与星期

- 用户明确给出日期时，使用该日期，并准确计算对应星期。
- 用户未给日期时，使用当前本地日期；默认按用户所在时区或系统日期处理。
- 日期统一写成“YYYY年M月D日（星期X）”，避免只写“今天”“明天”等相对日期。

## 整理规则

1. 只使用用户提供或可以直接推断的信息，不虚构完成结果、数据、原因、支持人或截止时间。
2. 按“工作结果—影响/效果—问题处理—后续安排”重组信息，不照搬原始记录顺序。
3. 效果部分优先保留数量、比例、耗时、质量、效率或覆盖范围等可验证变化；无量化数据时，使用准确的定性表达。
4. 每个发现的问题与对应处理方式放在一起，采用“问题1—解决/处理1、问题2—解决/处理2”的结构。
5. 尚未解决的问题，写明当前状态、影响和下一步；不要把猜测写成结论。
6. 区分“问题/风险”和“卡点/需要支持”，避免将普通问题直接写成外部依赖。
7. 尽量少用“了”，优先使用“完成、修复、输出、梳理、确认、优化、推进”等动词。
8. 语气专业、客观、简洁，避免夸张、空泛和过度包装。默认使用第一人称“我”，除非用户要求改成团队口吻或第三人称。

## 标准输出结构

```markdown
# 工作日报

**日期：** YYYY年M月D日（星期X）

## 一、今日进展

### 1. 今日完成
- 完成……
- 学习《文档名称》中的……，掌握……，并认识到……

### 2. 效果与提升
- ……

### 3. 发现的问题及处理方式
- **问题1：** ……
  **解决/处理：** ……
- **问题2：** ……
  **解决/处理：** ……

### 4. 卡点与需要支持
- **卡点：** ……
- **需要支持：** ……

## 二、明日计划

- [ ] ……
- [ ] ……
```

## 学习内容的写法

当用户提到阅读、学习、培训、技术文档、制度文档、方案或其他学习材料时，不新增独立的学习章节。将学习内容写入“今日完成”，先描述学习主题，再用一两句话说明掌握的重点、形成的认识或对工作的启发。

推荐使用以下描述性表达：

- 掌握……方法，能够用于……
- 理解……流程，明确……
- 认识到……对……的影响
- 结合文档内容，梳理出……
- 可将……应用于……

如果只提供文档标题而没有文档内容，不假装读过文档，可写“开始学习《文档名称》，具体收获待补充”，并保留用户原有表述。

## 异常兜底

| 异常情况 | 处理方式 |
|---|---|
| 没有任何工作内容 | 追问今日完成、问题/卡点和明日计划；用户暂不补充时，不编造日报内容 |
| 只有零散关键词 | 按结果和主题生成可用草稿，并在文末标记待补充信息 |
| 内容重复 | 合并同类事项，保留结果、影响和结论 |
| 信息相互冲突 | 标记冲突点，保留不确定性，不擅自选择结论 |
| 缺少效果数据 | 使用定性表达，或写“效果数据待补充”，不补造数字 |
| 有问题但暂无解决方案 | 写明当前状态和影响，将后续处理列入明日计划 |
| 缺少明日计划 | 写“具体安排待补充”，不擅自推测 |
| 仅提供学习文档标题 | 写明已开始学习，具体收获待补充，不扩展文档结论 |
| 用户要求压缩篇幅 | 保留日期、核心结果、关键问题处理和明日计划，删除次要过程 |

## 交互方式

- 用户提供完整记录时，直接输出最终日报。
- 用户提供碎片化记录时，先按结果和主题归纳，再输出可用草稿；不要简单按时间顺序复述原始记录。
- 用户只说“帮我写今天日报”但没有工作内容时，使用最少追问：今日完成什么、遇到什么问题或卡点、明日计划什么；若涉及学习文档，再询问文档名称、学习内容和初步收获。
- 用户要求“更简短”“更正式”“适合发群里”“适合汇报领导”时，只调整篇幅、语气和表达，不改变事实。

## 输出前自检

- 日期和星期准确。
- 今日完成、效果提升、问题处理、卡点支持和明日计划均有体现；无内容时明确标注“暂无”或“待补充”。
- 每个问题与对应处理方式逐项匹配。
- 学习内容放在“今日完成”，并使用描述性语言表达收获。
- 未虚构数据、原因、责任人、支持对象或截止时间。
- 重点放在结果和价值，不按时间顺序写流水账。
- 尽量减少“了”等完成时语气词。
