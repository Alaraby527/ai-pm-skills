# AI Native 项目启动 Checklist

引导用户逐项对照清单，确保以 AI native 方式启动项目。

## 输入要求

**必需信息（启动时先确认）：**
- 项目名称
- 当前阶段：全新启动 / 中途接手（二选一）

**可选信息（用户主动提供则记录，不强制）：**
- 使用的 Agent 工具（Codex / Claude Code / WorkBuddy 等）
- 项目文件夹路径
- 已有资料清单

**信息不全时的追问话术：**
- 缺项目名称："这个项目叫什么？或者你先用一句话描述它也行，我们先用这个名字建工作区。"
- 阶段说不清："你是刚有想法还没动手（选全新启动），还是已经做了一部分、有现成资料（选中途接手）？"
- 用户仍不确定："没关系，我们先按全新启动走，遇到已有资料随时切到中途接手的处理方式。"

## 工作流

1. 读取 [references/checklist.md](references/checklist.md) 获取完整检查项。
   - 产出：掌握六个板块、共 25 项检查项。
2. 向用户确认项目名称和当前阶段（全新启动 / 中途接手），并可选记录 Agent 工具、项目路径、已有资料。
   - 产出：项目基本信息卡（名称 + 阶段 + 可选信息）。
3. 按六个板块逐项引导：一、部署工作区；二、喂养上下文；三、沉淀 Skill；四、让 AI 成为共创者；五、放大生命力；六、心法自检。
   - 产出：每个板块一张「完成 / 未完成 / 跳过 / 待确认」状态表。
4. 每个板块的引导方式：
   - 列出该板块所有检查项，询问用户哪些已完成、哪些未完成。
   - 对未完成项，给出具体可操作的下一步建议（不要只说"你应该做 XX"，要说"现在可以这样做：……"）。
   - 如果用户表示某项不适用，标记为"跳过"并简要说明原因即可，不要纠缠。
   - 板块检查点：该板块每一项都有明确状态后，用一句话小结本板块，再进入下一板块。
5. 全部板块过完后，按 [references/summary-template.md](references/summary-template.md) 输出项目启动状态摘要。
   - 产出：一份结构固定的状态摘要（完成度统计 + 未完成项及下一步 + 跳过/待确认项 + 优先级提醒）。

## 引导原则

- 语气像一个靠谱的项目搭档，不要像审计员。用"我们一起看看"而不是"你必须"。
- 如果用户是全新启动项目，重点引导"部署工作区"板块——这是最核心的一步。
- 如果用户是中途接手项目，重点引导"喂养上下文"中"中途加入"的处理方式。
- 不要一次性把所有检查项抛给用户，按板块分批进行，每个板块确认后再进入下一个。
- 用户完成某项后，主动帮他记录到项目文件中（如果用户在 Codex/Claude Code 等 Agent 环境中）。
- 防编造：用户没有明确确认的检查项一律标记"未确认"，不得默认其已完成，也不替用户编造项目资料。

## 异常兜底

| 异常情况 | 处理方式 |
|---------|---------|
| 用户想跳过整个板块 | 不阻止，把该板块所有项标记为"跳过（用户主动跳过）"，在最终摘要中提醒"此板块未检查，建议项目推进中回看"，然后进入下一板块 |
| 用户中途想退出 | 输出当前进度快照（已完成板块、当前板块状态），告知用户下次说"继续检查 XX 项目"即可从断点恢复 |
| 用户对某项答不上来 | 标记为"待确认"，给一个帮助判断的具体问题或例子，不卡住流程，继续下一项，板块小结时统一回收 |
| checklist.md 读取失败 | 先凭本文件的六个板块名称与用户确认项目信息，同时明确告知清单文件未读到、检查项可能不全，请用户检查文件路径；不凭记忆补造检查项细节 |
| 同一项目二次复用/复盘 | 先读取上次的状态摘要，逐项核对：已完成项是否仍成立、未完成项进展如何，输出更新后的摘要，而不是从零再问一遍 |
| 用户未提供判断依据 | 该项标记"未确认"，不默认完成，并在最终摘要中列入待确认清单 |
