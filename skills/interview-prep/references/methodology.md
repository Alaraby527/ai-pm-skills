## 二、交叉验证结论（多源一致 = 必执行）

1. **面试是双向的**：Kelly「不是被选择」／海苔「把面试官当导师」／桂姐「唯一一次由你决定他问什么」。
2. **自我介绍的目的只有一个**：让面试官感兴趣，在他脑子里种钩子。
3. **必须有钩子结构**：这是两拨人独立提出的同一个机制的别名。
4. **项目讲述要公式化**：桂姐「背景-问题-过程-结果」≡ Kelly 的 STAR（但 Kelly 指出重点在 A）。
5. **必须写逐字稿 + 反复练**：海苔（对镜/录视频）／Kelly（讲给外行听）／桂姐评论区（每场录音复盘）。

## 三、两套自我介绍公式的映射

| 桂姐版 | Kelly 版 | 合并后的角色 |
|---|---|---|
| 定位 | 核心人设 | 一句话人设（须与 JD 匹配） |
| 证据 | 两个硬核故事 | 故事 A＝专业硬实力 / 故事 B＝软素质 |
| 动机 | 未来可期 | 为什么是这里 + 成长方向 |
| 钩子 | 在面试官脑子里种钩子 | 引导下一个问题 |
| — | 三个标签维度 | 素材来源：硬实力／软素质／**个人生命力** |

> 「个人生命力」是 Kelly 版独有、几乎所有人漏的一环，本 skill 强制保留为【生命力彩蛋】段落。

## 四、自我介绍的三条红线（不可违反）

1. **不得喊"匹配"**——喊出来就是邀请面试官反驳。让他从故事里自己得出匹配。
2. **不得空讲优势**（逻辑强、沟通好、学习能力强、抗压能力强）——优势只能由经历自然带出。
3. **不得念简历**，但**核心履历必须自己讲**——不讲的那段在面试官那里等于不存在。

## 五、STAR 的正确用法（多数人用反）

- ❌ 通病：80% 时间讲 S、T，A、R 一笔带过。
- ✅ 重点在 **A**：讲清在困境里做了什么决策、采取什么具体行动、为什么这么选。
- ✅ **A 与 R 强相关**：结果必须由你的行动直接导出。
- ✅ 团队项目：剥离"我的行动对团队成果的具体贡献"，不失真也不冒领。
- ✅ 实习生等价写法＝桂姐的「背景 → 问题 → 过程 → 结果」。

## 六、危机处理话术（Kelly 独家，写作时直接套）

| 场景 | 话术 |
|---|---|
| 脑子空白 | "我需要几秒钟整理一下。"（比硬挤答案体面得多） |
| 不确定他在问什么 | "您是想问 XX 对吗？"——**这不是减分项**，反而显示你在对准需求 |
| 压力面 / 知识盲区 | "这方面确实是我的知识盲区，基于我目前的理解我认为是 ___（给推理），如果不对请您指正，我回去立刻补。" ⚠️ 回去之后**真的补并发邮件补上思考**——极少有人做的加分项 |
| 答错被问倒 | 承认 + 给推理过程 + 追问正确思路。冷处理或转移话题最减分 |
| 紧张 | 权力感姿势（挺胸抬头）+ 自我暗示"我是来交流的，不是来受审的"+ 等待期轻量逻辑脑运动（背身份证号、做一道数独） |

## 七、七类必写题库

经历深挖 / 简历细节 / 事件层与动作层 / 经历追问 / 职业规划与岗位认知 / 行业与公司认知 / 方案题。
方案题必须按「拆解 → 假设 → 验证 → 指标」答，不得直接跳答案。

## 八、提问环节

原则：不要问百度能查的。既是最后一次补足印象，也是反向评估团队的窗口。
四个模板见 `assets/templates/ask-list.md`，其中「补救型」能扭转印象。

## 九、面试评价体系（反向对齐）

面试官在评四件事：**职业稳定性 / 过往能力与经验 / 培养潜力 / 眼缘儿**。
每一段逐字稿写作前先自问：这段话在证明哪一项？答不上就删掉。

## 十、AI 产品 / 技术岗专项

- 面试＝信息交互：接收端挖面试官提问背后的诉求；传递端主动立人设（**锚定优势 + 构建壁垒**）。
- AI PM 别炫技，**抓与传统产品的共性**：驱动逻辑是用户需求而不是 AI 技术。
- Demo 是在评估你跟进前沿的决心，要讲思考过程，避免"跟风做"。
- 需求来源从用户与行业洞察挖，而不是从模型能力倒推。
