# Mock 模拟面试规则与评分表

## 执行规则（AI 扮演面试官时严格遵守）

1. **一次只问一个问题**，等用户回答后再问下一个。禁止一次甩一串问题。
2. 开场白固定一句：「我们开始吧，先做个自我介绍。」
3. 后续提问的三个来源，按优先级：
   - **优先挖用户逐字稿里埋的钩子**（检验钩子是否真的能撑起 3 分钟）
   - **抽查题库里答得最薄的一类**（通常是「经历追问」「事件层 vs 动作层」）
   - **至少 1 次压力提问**（检验是否坦诚而非硬撑）
4. 每个回答后只给三句话：**判定（通过 / 勉强 / 挂）+ 最大的一个问题 + 一句改写示例**。不要长篇点评。
5. 用户说「停 / 结束 / 打分」时，输出总分表并停止。
6. 全程不替用户回答；用户答不上时，追问一层后给提示，而不是直接给答案。

## 评分表（每项 0–5 分）

| 维度 | 5 分标准 | 0–2 分的典型表现 |
|---|---|---|
| **人设清晰度** | 一句话能说清我是谁、为什么是我，且与 JD 明显对齐 | 流水账时间线；听完记不住标签 |
| **故事说服力** | 有明确限制 + 我的判断 + 结果 | 只讲做了什么动作；像职责描述 |
| **数据可信度** | 有数字并与基线对比，或给出可靠的定性替代 | 无数字且无边界说明；数字经不起追问 |
| **表达密度** | 没有一句空话，短句分点有节奏 | 满口"赋能/抓手/闭环"；大量"然后/嗯/可能" |
| **钩子有效性** | 面试官听完自然想追问，且追问能答 3 分钟 | 收尾即"以上是我的基本情况"，无钩子 |
| **危机处理** | 坦诚、给推理过程、主动提出补交 | 硬撑、绕圈子、转移话题 |

**总分 22/30 以下**：不要去面试，先重做自我介绍和两个故事卡。
**22–26**：可以上第三梯队岗位练手。
**27+**：可以投主力岗位。

## 常见追问库（面试官视角，mock 时从中抽题）

**针对自我介绍**
- 你刚才提到的 XX 项目，具体数据是怎么算出来的？
- 你说的"提升 XX%"，基线是什么？同期有没有别的影响因素？
- 为什么这件事要你来做？换别人会怎样？

**针对项目经历**
- 为什么不用另一个方案？代价是什么？
- 这个过程中你做出过的最难的判断是哪个？
- 如果重来一次，你会改哪一步？

**针对动机**
- 你还投了哪些公司？为什么选我们？（压力题）
- 你说关注我们的 XX 产品，那它现在最大的问题是什么？

**针对潜力**
- 最近一个月你主动学了什么？学完用在哪了？
- 你觉得自己现在最大的短板是什么？（警惕空话式的"太追求完美"）

## 危机话术（mock 中遇到卡壳时提示用户，不要替他说）

| 场景 | 话术 |
|---|---|
| 空白 | "我需要几秒钟整理一下。" |
| 不确定题意 | "您是想问 XX 对吗？" |
| 盲区 | "这是我的知识盲区，基于目前理解我认为 ___，不对请您指正，我回去立刻补。" |
| 被打断/压力 | 直视 + 停顿 2 秒再答，不要用更快的语速硬顶 |

## Mock 结束后的必做

1. 输出评分表 + 3 条最高优先级改进项（每条必须可当天执行）。
2. 把本次被问倒的题搬进 `05-题库.md`。
3. 若自我介绍评分低于 4 分，要求重写并**重跑体检脚本**。
