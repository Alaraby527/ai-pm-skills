# 04 项目故事卡 — {{PROJECT}}

> 一张卡对应一个项目。面试现场讲 ≤90 秒，追问层可以讲 3 分钟。
> 篇幅分配反着来：S 精简、T 只讲挑战点、**重点给 A**。

## STAR

**S｜背景（≤15%，两句话带过）**

> 当时的业务场景是 ___，已有方案是 ___。

**T｜任务（≤15%，只讲挑战点）**

> 我要解决的是 ___，难在 ___。

**A｜行动（≈50%，这是主战场）**

> 1. 我做的第一个判断是 ___，因为 ___（讲清为什么这么选）
> 2. 具体动作：___（角色 + 我亲手做的部分）
> 3. 遇到的阻碍是 ___，我绕开的方式是 ___
> 4. 我放弃的方案是 ___，放弃理由是 ___

**R｜结果（≈20%，与 A 强相关）**

> 结果是 ___（量化：从 X 到 Y，对比基线）。
> 定性价值：___（搭成了什么组件/流程/规范，后续被复用）

⚠️ **A 与 R 必须强相关**：结果必须是你的行动直接导出的，不要让结果像团队白捡的。
⚠️ 团队项目：清晰剥离"我的行动对团队成果的具体贡献"，不失真也不冒领。

## 三层追问预案（必写）

| 追问 | 我的答案 |
|---|---|
| 为什么这么做（而不是另一个方案）？ |  |
| 换个方案行不行？代价是什么？ |  |
| 回头看，哪里做得不够好？ |  |

## 表达检验

- [ ] 四要素齐全：背景 / 问题 / 过程 / 结果
- [ ] 信息密度：有没有一句话的空话？有就删
- [ ] 节奏：短句 + 分点 + 停顿，没有连续"然后…然后…"
- [ ] 讲给不懂这块业务的人听，他能说出"难在哪、我做了什么亮点、带来什么价值"
