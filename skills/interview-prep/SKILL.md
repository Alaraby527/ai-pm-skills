# 面试备战 Skill

## 简介

**干什么的**：帮 AI 产品经理系统化准备一场面试——从拆 JD 到写出可以直接开口念的逐字稿，再到模拟面试和面后复盘，全流程由 AI 陪跑落地。

**核心方法论**：桂姐求职规划的「定位-证据-动机-钩子」自我介绍结构 + 腾讯 18 年 HR 的「核心人设 + 两个硬核故事 + 未来可期」+ STAR（重点在 A）项目故事卡 + 项目素材 5 维度准备法 + 四大题型框架（项目深挖 / 行业认知 / 行为面试 STAR+R / 费米估算）+ AI PM 专项考点 + 分轮次通关策略。

**你能得到什么**：岗位分析表、异常值素材库、自我介绍 90 秒与 3 分钟双版本逐字稿（含体检报告）、STAR 项目故事卡、七类题库逐字稿、模拟面试评分表、反问清单、面后复盘表。

**与"给建议"的区别**：产出必须是**可以照着念的逐字稿**，并且自我介绍稿**必须跑体检脚本**机械校验，把"感觉不错"变成"可验证通过"。

**文件结构**：
```
interview-prep/
├── SKILL.md                          # 主文档
├── references/
│   ├── methodology.md                # 方法论细节与出处映射
│   ├── question-bank.md              # 七类题目的展开模板
│   ├── mock-rubric.md                # mock 规则、六维评分表、危机话术
│   ├── interview-prep-guide.md       # 项目深挖 14 道高频题与准备体系
│   ├── ai-pm-interview-questions.md  # AI PM 专项面试题与答题要点
│   └── prompts.md                    # 素材梳理 / 模拟面试提示词
├── assets/templates/                 # 8 个可直接填充的模板
└── scripts/
    ├── init_prep.py                  # 生成准备工作区骨架
    └── lint_intro.py                 # 自我介绍逐字稿机械体检（强制）
```

## 触发场景

- 面试不知道怎么准备，没有体系
- 自我介绍写不出来 / 写完了不确定行不行
- 项目讲不清楚、讲不深
- 遇到行业题 / 估算题就慌
- 行为面试答不到点上
- 需要 AI PM 专项面试题准备
- 想做模拟面试练习

## 输入要求

**必需信息**：
- 目标岗位/公司（或 JD）
- 个人项目经历（至少 1-2 个核心项目）

**可选补充信息**：
- 面试轮次（一面/二面/终面）
- 薄弱环节（项目表达/行业认知/估算题等）
- 面试时间（还有多久准备，决定走全流程还是急救模式）

**信息不全时的追问原则**（一次不超过 3 个问题，禁止因缺信息而自行编造经历或数据）：
- 缺 JD："把岗位 JD 发我（或链接），没有的话先给我一句『岗位名称 + 公司 + 业务方向』。"
- 缺简历/经历："把简历发我，或口述 2-3 段主要经历（时间/角色/做了什么/结果）。"
- 缺项目信息："挑 1-2 个你最核心的项目，简单说下背景、你做了什么、结果怎么样？我帮你梳理成标准化素材。"
- 缺轮次："是第几面？一面偏项目细节，二面偏行业认知，我会调整重点。"
- 缺时间："面试在什么时候？我按剩余天数排优先级。"

## 模式路由

先判断用户处在哪个场景，再决定走完整流水线还是单模块。

| 用户诉求 | 模式 | 执行章节 |
|---|---|---|
| 「帮我准备 XX 公司的 XX 面试」/ 给了 JD + 简历 | **A 全流程** | Step 0 → 9，全程执行 |
| 「帮我写/改自我介绍」 | B1 | Step 3（前置：至少拿到目标岗位一句话） |
| 「这个项目怎么讲」/「按 STAR 帮我改」 | B2 | Step 4 |
| 「帮我 mock 一下」/「模拟面试」 | B3 | Step 6 |
| 「帮我复盘这场面试」/ 给了面经回忆 | B4 | Step 8 |
| 「反问该问什么」 | B5 | Step 7（只出提问清单） |
| 距面试不足 48 小时 | **C 急救** | 跳过 1-2，直接 Step 3 + 5 + 7，控制在 20 分钟内产出 |

## Step 0：初始化准备工作区

当且仅当进入模式 A 或用户明确要求产出文件档时执行。用脚本生成目录骨架，避免每次手写同样结构：

```bash
python3 scripts/init_prep.py --company "腾讯" --role "AI产品经理" --dir "./面试-腾讯AI产品经理"
```

生成 01~08 号文件（岗位分析、素材库、自我介绍稿、故事卡、题库、提问清单、复盘表、时间表自检）。后续每一步都把产出写回对应文件，形成可复用资产。若用户只要对话式产出、不要文件，跳过此步。

## Step 1：拆 JD + 搞懂目标岗位

产出 `01-岗位分析.md` 四块内容：

1. **JD 四类信息**：核心能力要求 / 业务逻辑 / 上下游协同方 / 隐含软素质词。可直接把 JD 喂给模型并要求按这四类输出。
2. **三类关键词表**（硬技能 / 业务场景 / 软素质），按 JD 中出现频次与位置排序，标注权重。
3. **搞懂岗位四问**：这个岗位具体干什么 / 需要什么能力经验 / 处在公司哪个转化环节 / 对营收的作用是什么。答不上的必须明确写出来让用户补，禁止含糊带过。
4. **面试官评分锚**：职业稳定性、过往能力经验、培养潜力、眼缘儿——后续每一段逐字稿都要至少命中一项。

## Step 2：挖掘异常值（素材库）

产出 `02-素材库.md`，三步法执行：

1. **盘点**：把用户给的全部经历列出来（实习、课程项目、竞赛、社团、自媒体、个人项目），不预设"太小不值一提"。
2. **对标**：把 Step 1 的三类关键词列成对照表。
3. **提炼**：从经历中挑能佐证关键词且**与他人不同**的高光点，即"异常值"。无大厂实习时优先找自增/自发项目证据。

素材必须归入三个标签维度，缺一维要向用户追问：
- **硬实力**：专业能力、工具、方法论
- **软素质**：协作、推动、抗压、学习力
- **个人生命力**：让你从"能力集"变成"活生生的人"的标签（长期坚持的事、独特爱好、跨领域输入）

量化缺失的三种替代证据：相对对比（从没人做 → 我做成了第一个）、交付物（搭成了 XX 组件/流程）、边界说明（限制是什么，在此基础上做成了什么）。**不得编造数字**。

## Step 3：写自我介绍逐字稿（Skill 的核心交付物）

复制 `assets/templates/self-intro.md` 作为骨架。统一公式为：

```
① 核心人设（15s）→ ② 硬核故事 A/专业硬实力（35s）→ ③ 硬核故事 B/软素质（25s）
→ ④ 生命力彩蛋（5s，可选）→ ⑤ 动机/未来可期（15s）→ ⑥ 钩子（10s）
```

逐段写作要求：

| 段落 | 要求 | 硬性约束 |
|---|---|---|
| ① 人设 | 一句话标签 + 一个记忆锚点，必须与 JD 匹配 | ≤ 15 秒说完整 |
| ② 故事 A | 限制 → 我的判断/行动 → 量化结果 | 必须有数字或明确的定性替代 |
| ③ 故事 B | 冲突 → 我如何协调/推动 → 团队层面的结果 | 讲"我做了什么"，不是"我们做了什么" |
| ④ 彩蛋 | 一个让面试官觉得你像个活人的标签 | 一句话，不展开 |
| ⑤ 动机 | 具体到这家公司某个业务的判断 | 禁止"贵司平台大/技术氛围好"这类万能句 |
| ⑥ 钩子 | 埋一个最想被追问的点（深水区 / 失败复盘 / 业务判断） | 必须是可追问 3 分钟以上的内容 |

三条红线，写完后逐条自查：
1. **不得出现"匹配"及其同义口号**（匹配、非常适合、完全符合、我很契合）。要让人从故事里自己得出匹配。
2. **不得空讲优势**（逻辑强、沟通好、学习能力强、抗压能力强）。优势只能由经历自然带出。
3. **不得念简历**，但**核心履历必须自己讲出来**——不讲的那段在面试官那里等于不存在。

写完后**必须**跑机械体检（这是本技能区别于"给建议"的关键一步）：

```bash
python3 scripts/lint_intro.py 03-自我介绍稿.md --target 90 --keywords "用户洞察,数据驱动,跨部门协同"
```

脚本报告中的 ❌ 项必须修改后重跑，直到全部 ✅/⚠️。未见 ✅ 报告不得向用户宣称"稿子好了"。

同时产出 **90 秒版**与 **3 分钟版**两份，差别在于 3 分钟版的两个硬核故事展开到完整的背景-问题-过程-结果。

## Step 4：项目素材标准化 + STAR 故事卡

对每个要讲的项目，先按 **5 维度**备齐素材，再落成一张 STAR 卡（`assets/templates/story-card.md`）。

| 维度 | 内容要点 |
|------|---------|
| 项目背景 | 行业现状、业务天花板、用户未被满足的刚需 |
| 项目目标 | 核心指标、指标提升逻辑、数据预估依据 |
| 产品方案 | 策略分层设计，每条设计对应需求与权衡取舍 |
| 难点 & 亮点 | 平衡多方矛盾、创新解法、跨资源推动案例 |
| 结果 & 复盘 | 实际数据对比目标，可复用方法论 + 踩坑教训 |

→ 需覆盖项目深挖 14 道高频题，见 `references/interview-prep-guide.md`；梳理提示词见 `references/prompts.md`。

STAR 卡的写作要点：
- **S（背景）精简**，T（任务）只讲挑战点，重点篇幅给 **A（行动）**：讲清在困境里做了什么决策、采取什么具体行动、为什么这么选。绝大多数人把 80% 时间花在 S、T 上，这是最常见的失分点。
- **+ R（Reflection）复盘认知**：你学到了什么（产品经理必答项），缺 Reflection 不合格。
- **A 与 R 必须强相关**：行动必须直接导出结果，不能让结果像团队白捡的。
- **实习生/团队项目**要清晰剥离"我的行动对团队成果的具体贡献"，不失真也不冒领。
- 每张卡底部必须附 **3 层追问预案**：为什么这么做 / 换方案行不行 / 代价是什么。
- 讲清楚的检验标准：背景、问题、过程、结果四要素齐全；表达三要素达标——信息密度高（一句空话都不要有）、内容与对方需求匹配、有节奏感（短句 + 分点 + 停顿）。

## Step 5：七类题库 + AI PM 专项

参考 `references/question-bank.md`，为以下 7 类各写 1 份可直接念的答案：

经历深挖 / 简历细节 / 事件层与动作层 / 经历追问（失败与被否方案）/ 职业规划与岗位认知 / 行业与公司认知 / 方案题。

**答题框架**：
- 项目深挖题：结论先行 → 数据支撑 → 逻辑推导 → 复盘升华
- 行业认知题：竞品差异化四层拆解（业务定位→目标用户→产品设计逻辑→增长打法）；行业趋势判断四要素（规模&增速→线上化率→政策影响→用户需求变化→输出机会判断）
- 估算题/费米估算：拆解公式 → 逐层假设 → 合理性校验
- 方案题：拆解 → 假设 → 验证 → 指标，不得直接跳到答案

行业与公司认知类必须先检索该公司近期真实动态（产品动作、财报口径、竞品对比），不得凭印象编造。

**AI PM 专项考点**（详细题目 + 答案要点见 `references/ai-pm-interview-questions.md`）：
1. AI 应用开发 vs 底层原理的区别与市场占比
2. 为什么不能只调用外部 API（架构/数据安全/业务定制）
3. AI 产品场景设计能力（如云盘 AI 助手）
4. AI 项目的技术可行性评估
5. AI 项目资源与成本考量
6. RAG / Prompt 工程 / Agent 的基本原理与适用场景
7. AI 产品的评估指标（准确率/幻觉率/采纳率等）
8. AI 安全与合规

## Step 6：分轮次重点 + Mock 模拟面试

分轮次通关策略：

| 轮次 | 面试官 | 考察重点 | 通关要诀 |
|------|--------|---------|---------|
| 一面 | 直属 Leader | 项目真实性 + 做事逻辑 | 5 维度素材吃透，每个项目讲 3 分钟 + 深挖 15 分钟 |
| 二面 | 部门负责人 | 行业认知 + 复盘能力 + 职业规划 | 准备 3 个行业洞察 + 1 个清晰职业规划 |
| 终面 | HR/总监 | 价值观 + 团队适配 + 稳定性 | 谦逊清晰，表达成长意愿与长期规划 |

Mock 按 `references/mock-rubric.md` 执行，这是最能暴露问题的环节：

1. 明确告知用户：进入 mock 后 AI 扮演面试官，**一次只问一个问题**，用户回答后才继续。面试官人设 prompt 见 `references/prompts.md`。
2. 第一轮从自我介绍开始，后续问题**优先从用户逐字稿里埋的钩子深挖**，同时抽查 Step 5 题库中用户答得最薄的一类。
3. 每个回答后按 rubric 给「通过 / 勉强 / 挂」+ 一句最大问题 + 一句改写示例，不要长篇点评。
4. 插入 1-2 次压力提问，观察用户是否坦诚而非硬撑。
5. 结束时输出一份总分表（人设清晰度 / 故事说服力 / 数据可信度 / 表达密度 / 钩子有效性 / 危机处理）与 3 条最高优先级改进项。

## Step 7：反问清单

产出 `06-提问清单.md`，至少 3 个，且必须与岗位/公司近期具体动作绑定。参考模板：
- 业务落地型：如果我加入，您认为这个岗位前 3-6 个月最大的挑战是什么？期望我优先解决哪个问题？
- 卓越标尺型：您团队里表现最好的那 5% 的人，身上有什么共同特质？
- 大局观型：我注意到贵司最近在做 XX（具体动作），在这个背景下，这个岗位会面临什么挑战？
- 补救型（可选，大胆但有效）：刚才面试中您对我的经历或能力有哪方面的疑虑？我想补充。

禁止问可百度的问题（主营业务、公司人数...）。提醒用户：这也是反向评估团队的机会。

## Step 8：面后复盘

产出 `07-复盘.md`，重点复盘**被问倒的题和没发挥好的题**，不要复盘答对的。

对每个问题记录三件事：这道题在考察什么（基础 / 逻辑 / 业务洞察 / 价值观）、当时的答案、现在更好的答案。全部沉淀进 `05-题库.md`，形成可累积的面试题库。

## Step 9：心态与上场（不可跳过，但要快）

进入面试当天或前一天，输出一页《上场前 30 秒自检》，含三个心智锚点：
- 我不是来被挑选的，我是来双向评估的。
- 这是一次免费咨询——对面坐的是行业专家，这是低成本获取一手信息的机会。
- 前 3 分钟决定基础印象，也是全场唯一一次由我决定他问什么。

同时给出危机话术速查表（脑子空白 / 不确定对方在问什么 / 压力面 / 不会的题），详见 `references/mock-rubric.md` 的「危机话术」章节。紧张时的生理处理：权力感姿势 + 等待期做轻量逻辑脑运动（背身份证号、做一道数独）。

## 质量红线

1. **禁止编造**：没有的数据用定性替代（相对对比、交付物、边界说明），绝不虚构数字、公司名、项目结果。
2. **禁止空话成稿**：逐字稿里出现"赋能""抓手""闭环""平台大""技术氛围好"等万能句必须改写。
3. **自我介绍必须跑体检脚本**并通过，未跑不得交付。
4. **每个项目必须能讲 3 分钟版本和 15 分钟深挖版本**，只有一个版本不合格。
5. **行业认知题必须有自己的判断**，不允许只罗列事实没有观点。观点可以不对，但不能没有。
6. **每个 claims 都要有问责准备**：稿子里每一句陈述都预设面试官会追问"凭什么这么说"，答不上就删掉。
7. **不背标准答案**：提供的是框架不是台词，必须结合个人经历填充，千篇一律的模板回答扣分。
8. **AI PM 专项题必须展示技术理解力**，但不需要写代码——重点是"知道什么场景用什么技术、为什么"。
9. **保持双向视角**：提醒用户面试是双向评估，反问也是考察团队的机会。
10. **尊重用户的真实经历**：不为了贴合 JD 让用户撒谎；差距大时直言，并给"可迁移能力"的包装策略。

## 异常兜底

| 异常情况 | 处理方式 |
|---------|---------|
| 用户没有完整项目经历（转行/应届生） | 用实习/课程/个人作品替代，走 Step 2 异常值三步法，重点展示思维框架和学习能力 |
| 用户项目数据不好看 | 诚实面对，重点讲复盘认知和改进方案，不粉饰不编造 |
| 面试时间紧迫（< 3 天 / < 48 小时） | 切模式 C：直接 Step 3 + 5 + 7，先保 1 个核心项目素材 + 自我介绍 + 1 个行业观点 |
| 用户不知道目标公司考什么 | 基于 JD 和公司业务预判考点，标注"高频考点"和"可能考点" |
| JD 缺失或极简 | 先补一句「岗位名称 + 公司 + 业务方向」，再按同类岗位通用考点准备，明确标注是推测 |
| 模拟面试时用户答得差 | 不直接批评，指出具体问题（如"缺少数据支撑""结构不清晰"），给出改进示例 |
| 自我介绍体检脚本报 ❌ | 按报告逐条改后重跑，直到无 ❌，禁止跳过脚本直接交付 |
| Python 环境不可用 | 跳过脚本，改用 SKILL.md 中「自检清单」人工逐条核对（时长按 4 字/秒估算） |

## Skill 联动

- 项目素材梳理时，可用 `competitive-research` skill 做竞品差异化分析
