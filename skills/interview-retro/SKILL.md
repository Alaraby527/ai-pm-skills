# 面试复盘 Skill

## 简介

**干什么的**：把求职当成产品转化漏斗来复盘——每一层有行业均值，低于均值就是明确的短板信号。通过结构化复盘定位问题根源，而不是"感觉没发挥好"。

**核心方法论**：求职漏斗四层转化率诊断 + 面试复盘三步法（完整还原→分层定位→溯源根治）+ 显性/隐性短板分类 + 改进清单回流。

**你能得到什么**：求职漏斗诊断报告、面试问题清单、短板分类（知识/表达/匹配度）、改进优先级清单、下一次面试的具体行动项。

**文件结构**：

## 触发场景

- 面试挂了，想知道问题出在哪
- 投了很多简历没回应，想诊断转化率
- 一面/二面/终面特定轮次反复挂
- 想系统化复盘面试表现
- 求职一段时间没有进展，需要诊断

> **与 `resume-jd-align` 的边界**：连面试机会都没有（简历石沉大海）时，先去 `resume-jd-align` 做简历诊断；本 skill 从"有面试记录"开始。

## 输入要求

**必需信息**：
- 面试/求职情况描述（投了多少、面了几家、挂在哪一轮）
- 至少一场面试的回忆记录（问题、你的回答、面试官反应）

**可选补充信息**：
- 面试录音/逐字稿
- 面试官反馈（如有）
- 目标岗位 JD

**信息不全时的追问话术**：
- 缺面试记录："能回忆一下面试中问了哪些问题、你怎么回答的吗？哪怕是零散的记忆也可以，我帮你梳理。"
- 缺漏斗数据："目前投了多少份简历？有多少进了一面？多少进了二面？我帮你算转化率定位短板。"
- 只有情绪没有事实："我理解你的感受。我们先把情绪放一边，能具体说一个你觉得答得不好的问题吗？"

## 工作流（3 步）

### Step 1：完整还原

- 还原面试全过程：开场→项目讲述→提问环节→反问环节
- 记录面试官的反应：追问、皱眉、打断、点头、记笔记
- 记录自己的状态：哪里卡壳、哪里紧张、哪里答非所问
- 如有录音/逐字稿，逐句分析

**还原原则**：
- 不做评判，先客观记录
- 区分"事实"（问了什么、答了什么）和"感受"（觉得答得不好）
- 重点记录面试官追问的点（追问 = 没答到点上或感兴趣）

**检查点**：还原完成后，先向用户复述关键事实（问了什么、怎么答的），确认无误再进入短板定位。

### Step 2：分层定位

**求职漏斗诊断**：

| 漏斗层级 | 经验参考区间 | 低于参考区间时的高频问题 |
|---------|---------|------------------|
| 简历投递→面试 | 20% | 简历结构混乱、项目无数据、JD 匹配度低 |
| 一面通过率 | 35%-40% | 逻辑混乱、表达不同频、核心优势没体现 |
| 二面通过率 | 30%-35% | 无行业认知、缺少复盘、无清晰职业规划 |
| HR 终面通过率 | 70%-80% | 价值观/团队适配问题 |

> 注：以上为经验参考区间，无权威统计来源，不同公司/岗位/级别差异大；建议用你自己的投递数据校准后再判断（见质量红线 5）。

**短板分类**：

| 短板类型 | 表现 | 根因 |
|---------|------|------|
| **显性短板** | 问题不会答、知识点缺失 | 知识储备不足 |
| **隐性短板** | 答了但没深度、没数据、没结构 | 思考深度不够、素材没准备好 |
| **表达短板** | 知道但说不清楚、逻辑跳跃 | 缺乏练习、没有答题框架 |
| **匹配短板** | 能力够但没让面试官感知到 | 没有对齐 JD 关键词、没展示相关经验 |

### Step 3：溯源根治

- 不是补答案，是补底层能力
- 每个短板给出：根因分析 + 改进方法 + 验证标准
- 输出改进清单，按优先级排序
- 改进清单回流到 `interview-prep` 补强对应模块

## 质量红线

1. **复盘必须基于事实**，不允许"我觉得可能是因为…"式的无依据猜测。每个判断要有面试中的具体表现支撑。
2. **必须区分"不会"和"没说好"**：不会的补知识，没说好的练表达，两者改进方法完全不同。
3. **改进建议必须可执行**，不允许"多练习""加强学习"这类空话，要写清练什么、怎么练、练到什么程度。
4. **不制造焦虑**：客观分析问题，同时肯定做得好的部分。面试有偶然性，单次失败不等于能力不行。
5. **漏斗数据为行业参考值**，不同公司/岗位/级别有差异，不绝对化。

## 异常兜底

| 异常情况 | 处理方式 |
|---------|---------|
| 用户完全记不起面试内容 | 基于常见挂因清单引导回忆（"项目讲了多久？""有没有被追问数据？""反问环节问了什么？"） |
| 没有面试只有简历石沉大海 | 切换到简历诊断模式，建议用 `resume-jd-align` skill 优化简历 |
| 用户情绪低落 | 先共情再分析，不急于给建议；强调复盘是为了下一次，不是否定自己 |
| 多场面试复盘 | 按场次分别复盘，再横向对比找共性问题（共性问题 = 核心短板） |
| 面试官没有给出反馈 | 基于面试表现推断可能原因，标注"推测"，建议下次面试主动寻求反馈 |

## Skill 联动

- 简历投递→面试转化率低 → 用 `resume-jd-align` 优化简历
- 面试中发现项目讲不清 → 用 `interview-prep` 重新梳理项目素材
- 表达不流畅、逻辑跳跃 → 用 `script-polish` 打磨逐字稿
- 行业认知题答不好 → 用 `competitive-research` 做竞品/行业分析
