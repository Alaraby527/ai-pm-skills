# 审查提示词库

## 证据提取

```text
请只从作品集原文中提取可验证证据，不要补写事实。按以下字段输出：目标用户、具体问题、问题证据、AI 必要性、人机分工、工作流、失败案例、评测数据、迭代变化、业务结果、限制。每项标注原文位置，并区分“已有证据 / 合理推断 / 待补证据”。
```

## 项目硬伤审查

```text
请以面试官追问视角审查这个 AI 产品项目。重点判断：它是否只是模型套壳或一问一答；是否解释为什么不用规则/搜索/表单；是否展示了错误、回退、人工确认、评测和迭代。不要因为技术名词多就加分。输出硬伤、证据位置和最小修复动作。
```

## 版式审查

```text
请逐页审查这份作品集的扫描效率和可读性。检查每页主结论、标题是否结论式、信息层级、页面密度、字体大小、对齐、留白、颜色对比、流程图/截图是否服务于决策，以及导出后的裁切、模糊和重叠。把“影响面试判断的问题”和“纯审美偏好”分开。
```

## 事实安全改写

```text
请在不新增事实的前提下改写以下项目描述。保留所有真实数字、限制和不确定性；对缺少证据的地方使用“待补：...”标记，不要生成访谈、用户反馈、上线数据或模型准确率。优先改成“问题—判断—行动—证据—结果/限制”的结构。
```

## 面试追问

```text
针对这个项目生成 8 个高概率面试追问，覆盖：问题真实性、AI 选择、模型边界、工作流、异常回退、评测集、成本/延迟取舍、迭代与业务结果。每个问题后说明作品集中当前缺哪一条证据。
```
